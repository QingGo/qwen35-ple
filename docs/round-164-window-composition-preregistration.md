# Round 164 预注册：注入向量是模板的属性，还是条目的属性？

状态：**规则已冻结，实验尚未运行。**

- Part A（本地，已测）：窗口成分测量。这是分词器与模板的事实，不是关于模型的假设检验。
- Part B（需 GPU，未测）：贡献向量的跨条目相似度。**其预测由 Part A 导出，判定规则在本文冻结。**

Part A 先于 Part B 是设计的一部分，不是事后挑选：先测出窗口里有多少逐条信息，
再由那个数推出 Part B 的定量预测。

## 1. 这一轮问什么

Round 163 证明的界是

    I(future ; e_t | h_t) ≤ I(future ; w_t | h_t)

全部重量压在 `w_t` 上：注入的贡献 `c_t` **只是**寻址窗口的函数。整个"冻结嫁接
能带多少"的论证都从这里出发。

但这个式子里的 `w_t` 从来没被量过。这一轮先问它的前提：

> **答案位置的 12-token 窗口里，究竟有多少东西是"关于这一道题的"？**

窗口取自答案位置，因此它包含提示词模板的**固定后缀**。若后缀相对窗口很长，
那么 `c_t` 在相当大的程度上是**模板**的属性而不是查询的属性，界允许的空间
`I(future ; w_t | h_t)` 也随之对该任务更小。

## 2. 生产几何（读代码，不靠记忆）

```
ple_reference.py          pad_len = (conv_kernel_size - 1) * conv_dilation = (4-1)*3 = 9
official_ple_snapshot.py  ngram_size = 3      # 每个 gated_value 看 3 个 token
```

短卷积在 t 处的输出依赖位置 `t-9 .. t` 的 `gated_value`，而每个 `gated_value`
又依赖 `s-2 .. s` 的 token。**故窗口 = t-11 .. t = 12 个 token。**

模板（取自臂 JSON 的 `config`，非记忆）：

```
qa_prompt_template:        "Question: {question}\nAnswer:"
qa_boolq_prompt_template:  "Question: {question}\nAnswer with one word, Yes or No:"
```

条目集：`data/qa-standard/eval-600b.jsonl`，600 条（200 boolq / 200 nq / 200 triviaqa），
与两个 regime 的臂配置一致。

## 3. Part A — 结果（已测，本地）

复现：`scripts/analyze_window_composition.py`
产物：`outputs/round164/window-composition.json`

| 任务 | n | 后缀 token | 窗口内逐条槽位 | 后缀占比 | prompt 长度 min/中位/max |
|---|---|---|---|---|---|
| boolq | 200 | **10 / 12** | **2** | 0.833 | 42 / 133 / 540 |
| nq | 200 | 3 / 12 | 9 | 0.250 | 13 / 15 / 25 |
| triviaqa | 200 | 3 / 12 | 9 | 0.250 | 11 / 20 / 44 |

**BoolQ 的寻址窗口有 10/12 是逐题不变的模板。** 只有最后 2 个 token 随题目变化；
nq/triviaqa 是 9 个。这是本轮的第一个结论，且不需要任何模型前向。

## 4. Part A′ — 一个否定的设计结果（已测，本地）

本轮最初的设计是"按窗口 n-gram 在参考语料中的**稀有度**分层"（界的正面预测：
增益应集中在稀有上下文）。该设计**在当前资产下不可构造**：

| 参考语料 | token 数 | k=2 零计数 | k=3 零计数 | k=4 零计数 |
|---|---|---|---|---|
| PURE_WIKI | 990,455 | 73.2% | **96.0%** | 98.3% |
| PURE_STEM | 1,157,216 | 71.5% | 95.8% | 98.5% |
| PURE_CODE | 1,002,269 | 94.2% | 98.5% | 99.8% |
| COMBINED | 3,149,940 | 61.8% | **93.3%** | 98.0% |

在**表的寻址阶数**（k=3）上，93% 的条目计数为 0，取值只有 19 种——分位数退化成
`{0, 0, 1}`，没有梯度可言。三点推论：

1. 要支持 k=3 的分层，参考语料需要大约**两个数量级**以上的规模。
2. 要支持 k=4 需要约四个数量级。Round-160 发现"匹配字节下 4-gram 打平/胜过
   8/16-token"，而 4-gram 的稀有度在任何可负担的语料上都测不出来。
3. **在窗口尺度（k=9..12）上，"这段上下文模型见没见过"根本无法用数语料来估计**——
   任何可负担的语料里，几乎每个 12-gram 都是唯一的。

第 3 条是这一轮里最有价值的一句：**"稀有 n-gram"这个为查找表辩护的直觉，在窗口
尺度上不是一个可观测量。** 表能用三阶寻址，但它的输出依赖 12 个 token；两者之间
那 9 个 token，正是主干本来就已经有的部分。

网络策略核实：HuggingFace 不可达（`000`），GitHub/PyPI 可达。故大语料路线在当前
环境不可行，此结论不是推测。

## 5. Part B — 待测（需 GPU，一次短会话）

**问题**：若窗口主要由模板决定，那么固定一个 reader、跑同一批条目，注入向量 `c`
在 BoolQ 内部应当**比在 nq/triviaqa 内部更相似**——即使 BoolQ 的隐藏态 `h` 因为
段落内容不同而**并不**更相似。

**测什么**：对固定 reader，把 600 条 prompt 各做一次前向，在最后一个 prompt 位置
取 `model._last_reader_contribution`（`c`）与 `model._last_reader_hidden`（`h`）。
不做生成，不训练。

**统计量**（组内平均成对余弦，g ∈ {boolq, short}，short = nq ∪ triviaqa）：

    S_c(g) = mean_{i<j, i,j∈g} cos(c_i, c_j)
    S_h(g) = mean_{i<j, i,j∈g} cos(h_i, h_j)
    ΔS_c   = S_c(boolq) − S_c(short)
    ΔS_h   = S_h(boolq) − S_h(short)

**预测**（由 Part A 的 2 vs 9 个槽位导出）：

- **P1**：`ΔS_c > 0` —— 注入向量在 BoolQ 内更相似。
- **P2（使 P1 有意义的对照）**：`ΔS_h ≤ 0` —— 隐藏态并不更相似。若 `ΔS_h > 0`，
  相似性可能来自"BoolQ 条目本身长得像"，而不是窗口。
- **P3**：`S_c − S_h` 的差值在 boolq 上更大。

**reader**：`wiki` 与 `wiki-shuf` 各跑一遍。
`wiki-shuf` 是特异性对照：架构与范数相同、行内容被打乱。若主导项是窗口而非行内容，
两者应呈现**同样**的形态。若只有 `wiki` 呈现而 `wiki-shuf` 不呈现，说明主导项是
训练出来的行内容，P1 的解释需改。

**判定规则**（机械，置换检验）：

- 零假设：任务标签可交换。保持组大小 200/400 不变，置换任务标签 1000 次，重算
  `ΔS_c`；`p_c = (#{ΔS_c^perm ≥ ΔS_c^obs} + 1) / 1001`。对 `ΔS_h` 同法。
- **WINDOW_DOMINATED**：`ΔS_c > 0` 且 `p_c < 0.01` 且 `ΔS_h ≤ 0`。
- **ITEM_DOMINATED**：`ΔS_c ≤ 0`。
- **CONFOUNDED**：`ΔS_c > 0` 且 `p_c < 0.01` 但 `ΔS_h > 0`。

**防空洞检查**（三者缺一则本轮结果作废并如实报告）：

- 钩子确实在记录逐条差异：`c` 的组内平均成对余弦不得为 1.0（退化为常量）。
- `‖c‖` 与 `‖h‖` 的逐条值写入产物，供独立复核。
- 两个 reader 的结果都必须报告；不得只报符合预测的那一个。

**若要证伪本轮的读法**：只需 `ΔS_c ≤ 0`（BoolQ 的注入向量并不更相似），
或 `ΔS_c > 0` 但 `ΔS_h > 0`（无法归因于窗口）。

**实现与自检**：

- 执行：`scripts/round164_window_dominance.py`（一次前向/条/reader，无生成、无训练）。
- 判定逻辑的单元测试：`tests/test_round164_statistics.py`，在合成数据上覆盖四条分支，
  并显式断言**置换检验在可交换标签下不拒绝**（否则 `p_c < 0.01` 是白送的，
  其余断言都成了摆设）。
- 该测试在写脚本当天抓到一个真实缺陷：`_mean_pairwise_cosine` 用 `len(idx)`
  取组大小，而 `idx` 是布尔掩码，返回的是全表长度而非选中行数，`triu_indices`
  因此越界。**这在开机前修掉了**——Part B 需要 GPU，规则冻结之后才发现符号错误
  是最贵的失败模式。
