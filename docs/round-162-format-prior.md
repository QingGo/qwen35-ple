## 0. 预注册（本节在任何数字产生之前写入，之后不得改写）

### 0.1 被检验的断言

**主断言（要打死的那个）**：把检索到的记忆注入残差流，起的是**格式 / 协议先验**的作用。
在回答位置，寻址窗口只携带位置/格式信息，所以「格式」是记忆唯一能加的东西。
具体：round-156 在 4B 上观察到，**零注入**时模型吐对话脚手架
`\n\n<think>\n\n</think>\n\n...`，而**注入时（真行与乱序行皆然）**吐简洁的 raw 续写 ` yes`。

**竞争解释（必须能排除）**：这不是先验，而是「**层 2 上一发足够大的扰动打断了模型的对话模板**」。
在这个读法下记忆内容无关，没有格式先验，只有伪影。

### 0.2 六臂

同一冻结骨干、同一提示、同一读出架构、同一训练预算：

| 臂 | 训练行来源 | 评测行 |
|---|---|---|
| 1 `wiki` | PURE_WIKI | 真行 |
| 2 `code` | PURE_CODE | 真行 |
| 3 `stem` | PURE_STEM | 真行 |
| 4 `wiki-shuf` | PURE_WIKI | **乱序行**（同分布、等幅度，内容错配） |
| 5 `ple-off` | 读出器在位、贡献恒为 0 | — |
| 6 `no-reader` | 无读出器 | — |

决定性对比是 **1 vs 2 vs 3**。

### 0.3 预注册预测

* **P1（内容相关先验成立）**：臂 1/2/3 的**格式分布彼此不同**，且方向与各自训练语料一致
  （CODE 臂升高代码类续写/代码栅栏，WIKI 臂升高散文，STEM 臂升高公式/推理式续写）。
* **P2（扰动伪影成立）**：臂 1/2/3 **彼此不可区分**，且与臂 4 不可区分；三者（四者）
  一致地与臂 5/6 不同。
* **P3（无论哪种读法）**：臂 5 与臂 6 **应当彼此接近**（`--ple-off` 与无读出器在数学上
  都注入 0；差异只能来自实现路径）。
* **P4（内容依赖的词汇证据）**：若 P1 成立，则各臂生成文本的**领域词法指纹**
  （代码标记率 / 数学标记率 / 散文标记率）也应随训练语料移动；若 P2 成立，则不动。

### 0.4 否证条款（FALSIFICATION CLAUSE）

**若臂 1/2/3 彼此不可区分，则我的「格式先验」读法是错的**；诚实的结论是
「**注入扰乱了模板，内容无关**」。这是一个正当且有价值的结果，**必须照实报告，不得软化**。

### 0.4b 机械判决规则（同样在任何数字之前写定）

为避免事后挪动标准，判决由一个**固定算式**给出，参数全部来自数据本身：

1. **噪声地板**：臂 5（`ple-off`）与臂 6（`no-reader`）在数学上是**同一机制**
   （注入恒为 0）。它们之间的差就是本管线的**实现噪声地板**，
   记为 `F_scaffold`（脚手架率的逐条配对 |Δ|）与 `F_tv`（标签分布的 TV 距离）。
2. **内容效应量**：臂 1/2/3 两两之间脚手架率逐条配对 |Δ| 的最大值记为 `S_123`，
   其配对 SEM 记为 `SE_123`；标签分布 TV 距离的最大值记为 `S_tv`。
3. **判决**：
   * `S_123 > max(F_scaffold, 3·SE_123)` → **CONTENT_DEPENDENT**；
   * 否则 → **PERTURBATION_ARTIFACT**。
4. **co-primary 格式指纹**（同样在正式臂数字之前写定）：粗分类法可能对真实存在的格式移动**不敏感**——
   `'\n\nYes'` 与 `' Yes'` 在分类法下**都是** `raw_continuation/terse`，而这正是 round-156 头条
   （`\n\n<think>…` vs ` yes`）所在的那一层。因此同时用四个更细的**格式**描述子，
   各按同一「噪声地板 vs 1/2/3 内部最大」规则判一次：
   * `tv_label_dist`：分类法标签分布 TV；
   * `tv_prefix_dist`：**前导面**（`newline_lead` / `space_lead` / `no_lead` / `empty`）分布 TV；
   * `tv_joint_dist`：`label × 前导面` 联合分布 TV（**副判决**用这个）；
   * `tv_first_token_dist`：**首个生成 token id** 的分布 TV——比分类法更细，且正是
     round-156 指标 bug #2 讨论的那一层（` yes`=9542 vs `yes`=9405）。
   另报 `prefix_newline_lead` 的逐条配对 |Δ|（零注入的 `\n\n…` 形状）。
   > 这些描述子全部只描述**格式**（前导空白结构、首个 token），不描述**内容**；
   > 内容相关的证据另由领域词法指纹与 §3 的逐条阅读给出。
5. 同时报告「注入（1/2/3/4）vs 零注入（5/6）」的逐条配对差、McNemar 精确 p 与 TV，
   以确认**格式移动本身是否存在**（若不存在，本轮的诚实头条就是「该骨干上效应不复现」）。
6. 方向性预测（§0.3 P4）以**逐条配对、单侧 p** 检验：`code` 臂的代码标记 > `wiki` 臂、
   `stem` 臂的数学标记 > `wiki` 臂、`wiki` 臂的散文标记 > `code` 臂。
7. **操纵强度检查**（`scripts/run_round162_reader_crosseval.sh`）：三个读出器在三个语料的
   held-out 窗口上交叉评测 next-token loss。**若读出器没有在自己的语料上更低，则「内容无关」的
   结论不可解释**（可能是操纵没生效，而非内容不重要）。这一条是 null 结果的可解释性前提。

> 已知保守性：`F_scaffold` 若恰为 0（5/6 逐条完全相同），门槛退化为 `3·SE_123`，
> 仍能挡住「靠 n 制造显著性」的做法。
>
> 时序声明：§0.4b 写于任何**正式臂**数字产生之前；此前只跑过一次 12 条 / 12 步的**管线冒烟**
> （用于验证六臂脚本可运行、批大小不改变贪心输出）。冒烟数字不进入任何结论。

### 0.5 幅度控制（不可谈判，否则比较作废）

* 逐臂报告**注入贡献范数 / 注入层骨干隐状态范数**的比值。实现方式：给 `run_phase0.py` 加了一个
  **纯新增、默认关闭**的开关 `--qa-norm-stats`，它在每个解码步记录注入层上
  `‖contribution‖` 与 `‖hidden‖` 在**答案前一位**的比值（`qa_norm_ratio_mean / _median / _p90 /
  _of_means`）并写进 summary。默认关闭保证历史轮次逐位可比。
  （`models/` 全为 `--ple-off` 与 `no-reader` 时注入恒为 0，这些键不出现，即比值 = 0。）
* 用 `scripts/audit_reader_checkpoints.py` 检查：冻结张量跨臂**位级一致**、适配器**确实移动**、
  跨臂适配器范数比。
* **若臂间范数比超过 ~3×，比较被混淆，必须照实说明，而不是报告内容效应。**

### 0.6 测量口径（用解析器，不用字符串启发式）

本项目已被指标定义坑过两次（子串 EM 把脚手架臂虚高 33 点；gold NLL 在给模型不会吐的 token 打分）。
因此本轮：

* 逐条生成按**显式分类法**分类（`scripts/classify_format.py`，规则见 §2），报告**每臂完整分布**，不只报单一比率；
* 直接使用 `run_phase0.py` 已有的 `qa_fmt_scaffold_rate` / `qa_fmt_empty_rate` / `qa_fmt_distinct_rate` /
  `qa_fmt_boolq_yes_rate` 与 token 级 EM（**本报告确实使用了它们**，见 §5）；
* n 足够大，使分布移动能与噪声区分；报告 **n 与逐条配对比较 + SEM**，不只报边际率。

## 1. 设计理由（方法）

### 1.1 提示集的选择，以及为什么格式是「欠定」的

使用 round-156 同一套 **standard 1500**（`data/qa-standard/eval.jsonl`，BoolQ/TriviaQA/NQ 各 500）
与同一 raw 协议：

```text
Question: {question}\nAnswer:
Question: {question}\nAnswer with one word, Yes or No:      (BoolQ)
```

理由：**这是格式确实欠定的那个协议**。它是一条「补全式」提示，不在模型的对话分布里，
因此模型对它的续写存在**至少两个都合法的模式**——(a) 直接续写答案，(b) 从对话先验"逃逸"成
chat 脚手架（`<think>` / 角色标记）。round-156 正是在这里看到零注入走 (b)、注入走 (a)。
选任何**已经写死输出格式**的提示（如严格的 JSON-only 指令）都只会测到指令跟随，不是先验。

为把这一点做实，逐任务分开报告：TriviaQA / NQ 的提示只有 `Answer:`，是**真正欠定**的；
BoolQ 的提示含 "Answer with one word"，若脚手架臂仍然违反它，说明该指令在实践中并不约束格式。
（round-156 的 g0-nople 臂正是如此：吐 `<think>` 并幻觉新轮次。）

### 1.2 骨干与精度

**Qwen3.5-0.8B，float32，层 2 注入。** 理由：

* 6 臂 × (训练 + 评测) 在 0.8B 上是可承受的；4B 上同样规模会显著更贵。
* round-156 的格式效应是在 **4B + bfloat16** 上看到的。因此本实验**首先**要回答的是
  「在 0.8B 上这个效应**是否复现**」。若不复现，那本身就是发现（见 §7），
  **不得为了造出效应而去搜配置**。
* 精度选 fp32：0.8B 在 24GB 卡上 fp32 完全放得下，且避免 bf16 归一化/归约带来的
  逐位不确定性——本轮的比较是**跨臂**的，臂间任何数值噪声都应以最小化优先。
  （4B 路径必须 bf16 才能放进 24GB，这是 round-152 的约束，不是本轮的约束。）

### 1.3 唯一变量

除语料外全部相同：`--reader official --layer 2 --bridge-mlp --out-mlp`、
steps=500、seq-len=128、lr=1e-4、seed=0、同一 `--qa-sft-*` 配方、同一评测提示。
**臂 1/2/3 之间唯一改变的是 `--tokens-npy`**（即读出器在训练时看到的是哪一族 n-gram 行）。

> 语义澄清（重要）：「训练语料」改变的**不是评测时取回哪些行**（评测时行由提示 token 决定，
> 各臂相同），而是**读出器把这种 n-gram 行解释成什么**。因此 1/2/3 的对比恰好是
> 「同一张表、同一批行、不同的读出先验」——这正是「记忆内容是否决定注入语义」的最干净形式。

### 1.4 次要 regime：去掉 QA-SFT 混合

主实验沿用 round-152 的读出器配方（`--qa-sft-weight 0.5`，即在 `data/qa-standard/train.jsonl`
上做答案-only SFT 与语料窗口 1:1 混合），以便与 round-156 直接可比。但该配方有一个**自带的稀释**：
每一步有 50% 的概率抽到**各臂完全相同**的 QA 项，也就是说「语料」这一操纵只作用在一半的训练步上，
而且 QA 混合本身就在教读出器「在答案位置吐答案」——这**恰好是被测的那个格式先验**。

因此本轮**额外**跑一个 `NO_SFT=1` 的 regime（读出器**只在语料窗口上**训练，
`--qa-sft-weight 0`），作为**次要 regime** 报告。两个 regime 都报，谁的结论都不许单独冒充全部。

## 2. 格式分类法（显式、可审计）

`scripts/classify_format.py` 以**优先级级联**实现，首个命中者胜出：

| 序 | 标签 | 判定 |
|---|---|---|
| 1 | `empty` | `text.strip() == ""` |
| 2 | `chat_scaffold` | 含 `<think>` / `</think>` / `<|im_start|>` / `<|im_end|>`，或**独占一行**的 `system`/`user`/`assistant`，或 `assistant\n` / `user\n` |
| 3 | `code_fence` | 含 ``` ``` ```，或任一行以 `def `/`class `/`import `/`from X import`/`#include`/`public `/`function `/`fn ` 开头，或 ≥3 行以 `{`/`}`/`;` 结尾 |
| 4 | `json` | 去空白后以 `{`/`[` 开头且 `json.loads` 成功，或匹配 `^\s*[{[]\s*"?\w+"?\s*:` |
| 5 | `refusal` | 前 200 字符匹配 `i'm sorry / i am sorry / i cannot / i can't / as an ai / i'm not able / i don't know / unable to answer`（忽略大小写） |
| 6 | `raw_continuation` | 非空且未命中以上任何一类 |
| 7 | `other` | 解码异常（含 U+FFFD） |

`raw_continuation` 再按**首行长度**细分：`terse`（首个非空行的空白分词 ≤ 6 且无句末标点）与 `long`。

分类器另有三个**比分类法更细、但仍然只描述格式**的描述子：

* `prefix_class` ∈ {`newline_lead`, `space_lead`, `no_lead`, `empty`}——前导空白结构。
  round-156 的 `'\n\n<think>…'`（零注入）与 `' yes'`（注入）差别就在这一层，
  而分类法对 `'\n\nYes'` 与 `' Yes'` 给出**同一个**标签。
* `first_token_id`——首个生成 token 的 id。`271='\n\n'`、`2233=' No'`、`7179=' Yes'`、
  `9405='yes'`、`9542=' yes'`、`2083='no'`、`874=' no'`（已对真实 tokenizer 核实）。
  9405/9542 之差**就是** round-156 指标 bug #2 的那一层。
* 领域词法指纹 `domain:code / math / prose`（标记计数，规则写在分类器里）。

#### 3.6.1 副判决为什么按字面规则翻成 `CONTENT_DEPENDENT`（逐条公开）

§0.4b 的副判决算式是「`1/2/3` 内部最大 TV **vs 噪声地板 `F_tv`**」。
在 5/6 逐位相同的情况下 **`F_tv` 恰好为 0**，于是门槛退化成"**任何非零都算内容相关**"。
4B 的 `1/2/3` 内部最大 `tv_joint_dist` = **0.0017**，规则因此翻面。

**这 0.0017 是 600 条里的 1 条**（`S_123 × n = 0.0017 × 600 = 1.02`）。已定位到具体是哪一条：

| | 生成文本 | 分类 |
|---|---|---|
| `wiki` 臂 idx 473 | `Mount Elbert` | `raw_continuation` |
| `stem` 臂 idx 473 | `Mount Eel\n\n<think>\n\n</think>\n\nThe highest peak in the Ozarks` | `chat_scaffold` |

即 `stem` 臂在**一条**上答出 `Mount Eel` 后**短暂退回脚手架模式**再继续。
`wiki` vs `code` 的差别是 **0 条**（label 逐个相同）。

**三个独立读数都说这 0.0017 是噪声，不是内容效应：**

1. **小于产生它的那一臂自己的抽样地板**：`stem` 臂 split-half `tv_label_dist` = **0.0033**
   （0.0017 的 **2 倍**）。同一条臂对自己折半，就能产生比"跨语料差"更大的差异。
2. **首 token 同理**：1/2/3 内部最大 0.1483 vs split-half 地板 **0.3755**（2.5 倍）。
3. **主判决用同一条 0.0017 判出 `PERTURBATION_ARTIFACT`**，因为主算式带了 `3·SE_123` 这一项。

§0.4b 的备注**已经预见**了 `F = 0` 的退化，并写明"门槛退化为 `3·SE_123`"——
但那条备注只写在**主**算式下，**副**算式（四个格式描述子）没有跟着写。
**正确做法是把同一条退化处理一致地应用到副算式**（用臂内 split-half 地板替代 `F_tv`），
而不是在原式下报一个由单条文本决定的"内容相关"。

> **性质声明**：这是**事后澄清（post-hoc clarification）**，不是事后移动标准。
> 我把它单列出来、给出具体是哪一条文本、并说明三个独立读数，就是为了让它可被反驳 ——
> 而不是把它静默地套用掉。若读者不接受这条澄清，那么诚实的表述是

| **脚手架压制**（`chat_scaffold` 0.177 → 0.000） | **无关** | 三臂全部压制，差异 ≤ 0.01 |
| **其余输出分布**（前导面、首个 token、词法标记、长度） | **有关** | 四个描述子全部越出地板；两条方向性预测通过 |

**但它不推翻界，反而补上了界的另一半。** 界说的是
`I(future ; e_t | h_t) ≤ I(future ; trigram | h_t)` ——
即这条通道**能**承载表的 trigram 统计。语料的表面统计（wiki 的散文性、code 的代码标记）
**正是** trigram 先验，界**预测**它会出现。主实验看不到它，是因为答案被压到 2.5 token，
**没有地方表现**。

所以本文的结论应当重写为：

> **这条记忆确实携带"语料特有的先验"，但它是 trigram / 表面先验，不是知识。**
> 饱和时它表现为与内容无关的格式压制；一旦给出长度空间，语料的词法签名就显出来
> （散文 +0.69、代码 +0.033）。**始终没有出现的是段落后文条件化的召回**
> —— round-161 的知识探针为零，那才是界禁止的部分。

**必须写明的两条限制**：

1. **配方与规模不同**：`NO_SFT=1`（无答案格式 SFT）且只有 600 条，
   与主实验的 1500 条 / 六臂不同批次，不能与之并列引用，只能作为
   "天花板撤掉后会怎样"的证据。
2. ~~缺 `ple-off`~~ → **已补齐，六臂齐全，完整预注册规则适用**（见上表）。

## 6. 判决与头条

### 6.1 一句话头条

> ⚠️ **本头条的适用范围已被 §3.7 限定**（六臂齐全后的完整机械判决见该节）。 下面是**饱和 regime**（答案被压到 2.5–2.7 token）的
> 正确陈述；撤掉天花板后，格式**是**内容相关的（四个描述子全部越出地板，两条方向性预测通过）。
> 无条件的「与内容无关」是**错的** —— 准确的读法是"**脚手架压制**与内容无关，
> **其余输出分布**有关，且后者正是界预测的 trigram 先验"。

> **在饱和 regime 下，格式迁移是「扰动伪影」，与记忆内容无关。** 在 round-156 看到效应的那个骨干上
> （Qwen3.5-4B，bf16，层 2），零注入的模型 **95.8%** 吐对话脚手架 `\n\n<think>…`、
> 平均 31.2 token；注入任意一个语料训练出来的读出器都把它压到 **0.0%** 脚手架、2.6 token
> （600 条里没有一条共享同一个首个 token，McNemar p = 1.6e−173）。与此同时
> PURE_WIKI / PURE_CODE / PURE_STEM 三个读出器**注入的向量彼此只有 cos 0.73–0.76**，
> 格式分布却**完全相同**（TV = 0.0000；`stem` 相差 0.0017，**小于该臂自己折半的 0.0033**）。
> 同一结论在 0.8B + fp32 上独立复现（脚手架 0.195 → 0.000，n=1500/臂，p = 1.3e−88）。

英文版（可直接进 README / paper）：

```text
The format shift is a perturbation artifact independent of memory content.  On the
backbone where the effect was first seen (Qwen3.5-4B, bf16, layer 2), zero injection
makes the model emit chat scaffolding on 95.8% of items (mean 31.2 tokens), while
injecting a reader trained on PURE_WIKI, PURE_CODE or PURE_STEM alike suppresses it to
0.0% (mean 2.6 tokens; not one of the 600 items shares its first token with the

different vectors (pairwise cosine 0.73-0.76) yet produce identical output-format
distributions (total variation 0.0000; the largest cross-corpus spread, 0.0017, is a
single item out of 600 and sits below the split-half floor of the arm that produced it,
0.0033).  The same null reproduces
independently on Qwen3.5-0.8B in fp32 (scaffolding 0.195 -> 0.000, n=1500 per arm,
```

> 那里把性质（事后澄清）、具体文本、与三个独立读数都摊开了。

### 6.3 一个必须写清楚的例外：臂 4 与臂 1/2/3 **不**可区分这个预测是错的

预注册 P2 说"四者（1/2/3/4）一致"。实测**不是**：`wiki-shuf`（同一个 `wiki` 读出器、
评测时行被打乱）与三臂差别很大——空串率 +0.126，脚手架 +0.025，长度 2.5→6.3，
联合 TV 0.8933，首 token 相同率 0.0753。

这不推翻主判决，但把结论**收紧**成一句更准确的话：

> **记忆的「内容」不影响格式，记忆的「对齐」影响。** 注入向量是否与该位置的 n-gram 匹配，
> 决定输出是否退化（乱序 → 12.6% 空串、更长的乱码式续写）；而它由哪个领域的语料训练而来，
> 对格式**没有任何可测影响**。

也就是说：本轮的否证对象是**「领域内容 → 格式先验」**这一条；「记忆携带位置相关先验」这条
（round-161 已从表侧证明）**没有被否证**，反而被臂 4 的退化侧面支持。

### 6.4 对 round-156 的重述

round-156 观察到「注入把 4B 从 chat 脚手架压回 raw」，并把它读成"PLE 首先是格式先验"。
本轮在 0.8B 上**复现了现象**，但**否证了那个读法的一半**：现象与**有没有注入**强相关，
与**注入的是什么**无关。正确的措辞是
「**注入把模型推离对话模板**」，而不是「注入提供了格式先验」。

## 7. 什么会使本结论错

1. **幅度混淆**（已排除，但口径要写死）：若臂 1/2/3 的注入范数相差 >3×，比较作废。
   实测（0.8B）：参数级 0.997–1.045×（audit）、解码级 ratio_of_means 1.10×、固定提示级 0.96–1.10×。
   若换 seed、换训练步数使范数比越界，§3 的 null 立即失效。
   4B 的参数级审计同样通过（0.886×–1.008×，见 §4.1）；4B 的**注入向量级**对照
   （§4.2 那个仪器）由跟随队列在 4B 完成后补跑，产物 `outputs/round162-4B/contribution-similarity.json`。
2. **操纵没生效**（已用 §4.2 排除，但这是最强的辩护方向）：若三臂注入向量近乎共线，
   "内容无关"只是"读出器相同"的同义词。实测余弦 0.73–0.76，故不成立。
   **残余风险**：三者仍有 73% 的共享方向（很可能来自各臂完全相同的 QA-SFT 混合），
   本实验只证明了**剩下的 27% 不影响格式**，没有证明"任何内容差异都不影响格式"。
   `reader_contribution_similarity.py` 用 192 条提示，若换成别的提示集有系统性差异，需重测。
3. **天花板效应**：臂 1/2/3 的格式分布是**退化**的（100% raw、100% no_lead、99% terse、
   中位 2 token）。在一个已经贴顶的轴上，"无差别"可能是**没地方表现差别**，
   而不是"没有差别"。§3.5 的冠词残差正是这种"溢出到内容轴"的表现。
   → 这是 `NO_SFT=1` regime（§1.4）存在的理由：去掉答案格式训练后生成长度不再被压到 2 token。
   **若两个 regime 结论不一致，以"内容仍然不影响格式"为可报告结论、以"贴顶"为解释。**
4. **n 与抽样**：n=1500/臂、500/任务。首 token 的臂内 split-half TV 0.246–0.259 就是
   这个 n 下的抽样地板；任何小于它的臂间差**不可报告为差异**。格式标签轴的 split-half 为
   0.0000 是因为这些轴在臂内完全恒定，不代表对小效应敏感。
5. **解析器**：分类法是有文档的规则级联，`chat_scaffold` 的标记集**刻意与 `run_phase0`
   的 `_FORMAT_MARKERS` 对齐**（因此继承了它把 `Nouser` 判成含 `user\n` 的过度触发）。
   自建分类器与 `run_phase0` 在六臂上给出完全相同的小数（§5.1），互为校验；
   但两者不独立，同一个标记集错了会一起错。
6. **任务构成**：效应在 BoolQ 上只有 0.048，在 NQ/TriviaQA 上是 0.27。
   任何在**前 N 条**（=全是 BoolQ）上做的冒烟都会得出"效应不存在"的错误结论——
   本轮自己就先犯了一次（§3.1 的注）。若换提示集或换采样顺序，效应量会变。
7. **骨干与层**：结论在 **Qwen3.5-0.8B + fp32** 与 **Qwen3.5-4B + bf16** 两个骨干上都成立
   （§3 与 §3.6），但两者都是 **`--layer 2`** 注入。
   另外 round-163 指出官方 PLE 挂在 **0-based 第 1 层**，而本仓库主线（149/152/156/162）
   一律 `--layer 2`（第三层）。**本轮的否证因此只覆盖层 2**；
   层 1 的版本未被排除（也未被支持）。
8. **是否有内容效应存在于别的读出指标上**：本轮只测了格式与领域词法。
   §3.5 的冠词差异说明内容**有**微弱影响（在答案串层面）。因此"内容无关"必须限定为
   **"对格式分布的任何一轴无影响"**，不能说成"内容完全无用"。
