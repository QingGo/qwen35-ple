## 0. 预注册判读规则（在产生任何数字之前就打印在产物里，此处原样引用）

```text
PRE-REGISTERED INTERPRETATION RULE (fixed before any number below was computed)
  * tail share of NLL large AND verbatim hit rate high at k>=4  => strong candidate for external memory; quantify how much of the tail is memorisable.
  * tail share small OR verbatim hit rate ~0                     => external memory has no niche on this distribution regardless of how good the read-out is.
  * if NO corpus in the set beats PURE_WIKI materially on those two axes, the honest conclusion is that the limitation is a property of n-gram memory itself, not of prose, and the round-157/158 verdict generalises.
```

规则本身不可判定（"large / high / materially" 没有阈值），所以在**看数字之前**固定了操作化定义，

## 1. 结论（先说，再给证据）

1. **不是方法属性，是分布属性。** 在四个分布里，**代码（PURE_CODE）在"可记忆性"这条轴上显著优于散文**：
   4-gram 逐字续写可用率 0.484 vs WikiText 0.112（4.3×），k=16 时 0.208 vs 0.0017（**122×**）；
   在 graft 自己的上下文长度（trigram，k=3）上，"可寻址且可记忆"的 NLL 质量是 **0.294 vs 0.158（1.9×）**。
   因此 round-157/158 的判决**不能原样推广**：它是关于散文/网页文本的陈述。
2. **但"尾部占比"这条轴不区分分布**：四个语料的 count≤10 尾部 NLL 占比都在 0.75–0.94，
   WikiText 0.880 甚至不是最大也不是最小。**尾部大是普遍的；能不能记住才是区分点。**
3. **量级仍然有限，而且 graft 拿不到大头。** 即便在代码上，"可寻址 + 可记忆"的 NLL 质量也只有 **≤29%**；
   而 bucket 0（trigram 上下文在训练流里根本没出现过）占代码 36% 的位置、**63% 的 NLL** ——
   计数表对它**没有行可查**（对从万亿 token 预训练来的冻结表则未必，见 §5 警告）。
   代码上 k≥4 的记忆性爆炸（0.250 vs k=3 的 0.294，衰减很慢）恰恰是 **trigram 键控的 graft 用不到的那部分**。

按预注册规则逐条判定：

| 规则条目 | 判定 | 依据 |
|---|---|---|
| 第一条（尾大 **且** k≥4 命中率高） | **仅 CODE 接近**；以主口径（去污染位置集）差 0.016 未过（0.484 vs 0.50），以未去污染口径过线（0.540） | 见 §3、§4 |
| 第二条（尾小 **或** 命中率≈0） | 四者皆不成立（尾部都大、命中率都不为 0） | 见 §3 |
| 第三条（没有任何语料在两条轴上materially优于 WIKI） | **不成立**：CODE 在记忆轴上以 4–122× 超过 WIKI ⇒ 判决**不**推广 | 见 §2–§4 |

## 5. 让这些数字不可信的地方

1. **"可记忆"≠"有用"**：命中率只问"金标续写在训练流里跟过同一个上下文吗"。
   计数为 1 的续写给出的是很弱的分布；真正的增量还取决于**排序**与 backbone 已经会什么。
   本轮的 0.294（代码，k=3）是**上界**，不是可期待增益。
2. **训练流只有 792k tokens**：4-gram 层的单次出现比例 —— WIKI **94.1%**（629,531/668,773）、
   CODE **72.8%**（196,597/270,184）、STEM **72.8%**（352,950/485,005）、FINEWEB **94.8%**（676,207/713,036）。
   这本身就是分布差异的直接证据（代码/STEM 的 4-gram 有近三成会重复出现），但也意味着
   bucket 0 占 36–76% 的位置。绝对 NLL 会随语料增大继续下降；**只有同一行内的横向比较是稳的**。
3. **去污染窗口与分析窗口相互作用**：位置级去污染（64-token，`--position-decon-ngram`）会**恰好删掉**
   重复出现的片段 —— 而那正是"记忆性"现象本身。所以：
   * NLL/top-1/尾部占比用去污染口径（保守，不让计数模型白拿"见过原文"的分）；
   * 命中率同时给出去污染口径与**未去污染**口径（§4），后者不被过滤器压制。
   * 代价：代码上 64-token 过滤删掉 21,618/198,028 = **10.9%** 的位置（16-token 口径 30.7%），
     WikiText 删 0（16-token 口径 0.2%）。这个删除量本身就是分布差异的证据。
4. **bucket 0 ≠ 不可寻址（对 graft 而言）**：本分解的分母是 **1M token 语料**。
   冻结的 PLE 表来自 Qwen3.8 的万亿级预训练，一个在 1M 语料里"没见过"的 trigram
   在预训练里几乎肯定出现过（且有行）。所以 §3 的 bucket 0 对**计数表**不可寻址，
   对**冻结表**可能可寻址 —— 本轮无法测量后者的行覆盖率。
5. **PURE_FINEWEB 来源不同**：它不是 build_mix 产物，而是"预分词 dump 的前 N 个 token"
   （manifest 自述；无 eos、无记录结构、连续自然流而非打乱记录）。虽然解码验证其 token 在 Qwen3.5 词表空间内
   （示例文本连贯），但它的 train/eval 是**连续文档**切分，与另外三个"打乱记录"切分不同；
   它的命中率因此可能被文档内部的重复抬高。**FineWeb 行应视为暂定。**
6. **候选集是各语料自己的 top-5000**（各自的词频排序），不是跨语料统一的固定集合；
   全词表列覆盖各自训练词表（未登录 token 分数恒为 floor，不影响 argmax 排序）。
   V_uni 统一取 248,070（= 四语料最大 token id + 1），比 round-158 的 248,047 大 23，floor 差异 ~1e-5 nats。
7. **STEM 的文档级补集几乎被掏空**：817 条补集记录里 752 条（92%）与训练流共享 ≥16-token 跨度，
   只剩 44,577 tokens 可用（8-token 口径则是 100% 被删）。因此 STEM 的文档分离对照样本很小。
8. **一个 round-158 的更正**：round-158 声称"四个阶数位置集合完全相同"，实现上低阶模型其实多算了 1–3 个位置
   （per-order n_positions 为 1,152,891/…/1,152,888）。本轮已修正为真正相同的集合；
   NLL 变化 ≤4.5e-6 nats，所有已引用的 4 位小数不变（7.3202/5.5634/5.3759/5.3368）。

## 6. 复现命令（全部在 16 核 / 120 GiB 的新机上，`flock` 串行）

```bash
PY=/root/autodl-tmp/qwen35-ple/venv/bin/python
COMMON="--orders 1,2,3,4 --smoothing mkn --uniform-vocab 248070 --candidate-from train \
  --acc-positions 20000 --acc-positions-full 2000 --acc-candidates 5000 --acc-chunk 500 \
  --scaling-prefixes 0.25,0.5,1.0 --position-decon-against train --position-decon-ngram 64 \
  --decon-sensitivity 16,32,64,128 --tail-analysis --verbatim-ks 1,2,3,4,8,16"

# 主实验：四语料同几何（train 792,364 / eval 198,091，同位置集合）
for C in PURE_WIKI PURE_CODE PURE_FINEWEB PURE_STEM; do
  flock /tmp/qwen35_heavy.lock $PY scripts/bench_ngram_reference.py \
    --train-npy data/phase1/$C/tokens.npy --train-cap 792364 --holdout-tail 198091 $COMMON \
    --source-text data/phase1/$C/corpus.txt \
    --output outputs/round159/ngram-dist-$C.json --markdown outputs/round159/ngram-dist-$C.md
done

# 次实验：文档级不相交补集（Wiki/Code/STEM；FineWeb 无源记录，无法做）
for H in wikitext:PURE_WIKI PURE_CODE:PURE_CODE PURE_STEM:PURE_STEM; do
  flock /tmp/qwen35_heavy.lock $PY scripts/bench_ngram_reference.py \
    --train-npy data/phase1/${H##*:}/tokens.npy --train-cap 792364 \
    --eval-npy data/phase1/${H%%:*}-heldout-decon/tokens.npy $COMMON \
    --source-text data/phase1/${H##*:}/corpus.txt \
    --output outputs/round159/ngram-comp-${H##*:}.json --markdown outputs/round159/ngram-comp-${H##*:}.md
done

# 切分构建（本地，需 tokenizer；PURE_CODE/PURE_STEM 各 ~1 分钟）
python scripts/build_corpus_heldout.py --corpus-dir data/phase1/PURE_CODE \
```
