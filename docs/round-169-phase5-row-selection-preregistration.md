## 1. 为什么下一步不是优化器,而是行选择

问题:训练行总是略微有害,是不是优化器不够好,换个优化器(Muon / 别的)就能找到更优参数?

**不是。** 判据来自我们自己的数据:

| 读法 | 目标 | 状态 |
|---|---|---|
| 优化问题 | 更好地最小化**训练流**损失 | **没失败** —— lr=1e-4 的损失 2.9739 → 2.9556 → 2.9371 → 2.9178,四轮单调下降 |
| 泛化问题 | 更好地最小化**留出流**损失 | **这才是失败所在** |

而伤害**关于行位移单调,且从不转正**:

```text
kept_delta_rms  2.40e-03 → Δ = −0.00272
                6.01e-03 → Δ = −0.06379
                1.82e-02 → Δ = −0.33127
```

⇒ **一个"更强"的优化器会把训练损失压得更低,也就是让行走得更远,于是更差。**
除非它能在**同样的损失下降下走得更少** —— 那不是收敛速度问题,是**收缩(shrinkage)**问题。

**但确实存在一个优化器病理,而且它正是稀频受害的机制。**
`SparseAdam` 逐坐标尺度不变,某行**第一次**被更新时:

```text
m̂/√v̂ = g/|g| = sign(g)   ⇒   第一步 = lr · sign(g)     ← 与证据量无关
```

**一个只出现 1 次的三元组,拿到一次满步长、方向由单个噪声样本决定的更新。**
冻结行是从整个语料估出的先验,这一步等于用 1 个样本把它替换掉。
这解释了"稀频带受害、高频带受益",也解释了 lr=1e-3 下 **80% 的伤害发生在第一轮**。

**Muon 为什么是错的工具**:它用 Newton–Schulz 正交化动量矩阵,是为**稠密二维权重**设计的。
放到稀疏按行的嵌入表上有三条冲突:(a) 一步只碰 ~500/667,404 行,行与行是**独立参数**,
没有可正交化的矩阵结构;(b) 正交化会**混合行**,人为制造串扰;
(c) 它给**小梯度方向满尺度更新**正是其卖点,而我们的稀频行**已经是**满尺度。
**Muon 放大这个失效模式,不修它。**

所以正确的修法是**步长随每行的证据量收缩**。本阶段测它的极限情形:硬掩码。

## 3. 规则

```text
臂 A: --min-train-count 10   硬掩码;count < 10 的行保持冻结 E0 值
      lr = 1e-4, epochs = 4, arm = real, seed = 0   ← 除掩码外与 lr=1e-4 基线完全相同

臂 B: --min-train-count 50   仅当臂 A 落在容差内才执行(见 §5)
```

不变量:同一个 `E0`、同一个 reader、同一条训练流与留出流、同一 `keep-index`、
同一 `batch_tokens`、同一 seed。**唯一变量是"哪些行允许移动"。**

## 4. 预测 —— 这是**恒等式**,不是带误差的预报

硬掩码把 count < N 的行**逐位保持**在冻结值。对那些位置,eval 的两个臂注入**同一个向量**,
所以 `delta = frozen − trained` **精确为 0**。
又因为 `trigram_codes` 是**单射不是哈希**,每个不同三元组独占一行,
所以冻结低频行**不会改变**高频行的轨迹(它们的梯度从不混合)。

⇒ 总体 Δ = (被训练的频带之和) / 打分位置数,**没有自由参数**。

从 `reband-lr1e-4.json`(phase 4 产物,先于本阶段)读出:

| 阈值 N | 训练的位置 | 预测 Δ |
|---|---|---|
| 1(全训,对照) | 443,460 / 443,460 (100.0%) | **−0.0027166083** |
| 2 | 341,424 (77.0%) | −0.0003240540 |
| 5 | 248,038 (55.9%) | +0.0051043085 |
| **10(臂 A)** | **196,397 (44.3%)** | **+0.0074002256** |
| 20 | 156,312 (35.2%) | +0.0076494504 |
| **50(臂 B)** | **113,591 (25.6%)** | **+0.0069824346** |
| 100 | 85,409 (19.3%) | +0.0064461364 |

**恒等式的自检**:阈值为 1 时上表给出 −0.0027166083,而实测量是
**−0.0027166083429033976** —— 十位小数一致。这一步在跑任何新臂之前就验证了分解本身。

**规模上的一个事实**(它决定了这一级的意义):667,404 行里只有 **5,063 行**的训练计数 ≥10
(0.8%),而这 0.8% 的行覆盖了留出流 **44.3%** 的打分位置。快照被单例主导。

## 5. 判定规则(冻结)

```text
确认 "选择性训练优于冻结":   Δ_A > 0  且  |Δ_A − 0.0074002256| ≤ 2e-4
恒等式被证实:                同一条件(分解不只是拟合,是可预报的)
臂 B 执行条件:               |Δ_A − 0.0074002256| ≤ 2e-4
                            否则停,并报告分解不成立

证伪:                        Δ_A ≤ 0            → 分带分解是错的
                             |Δ_A − 预测| > 2e-4 → 它有隐藏变量,不是恒等式
```

**容差为什么可以这么紧**:掩码行的轨迹与未掩码运行**逐位相同**(同样的批次、同样的顺序、
同样的 seed、冻结的骨干与 reader),所以被训练位置上的逐位置 Δ **就是** lr=1e-4 那一臂的值。
剩下只有 CUDA 浮点非确定性,量级远小于 2e-4。相对效应 7.4e-3,这个容差是 2.7%。

## 6. 这一级的**上限**,先说清楚

即使完全成立,**Δ = +0.0074 nats 是注入收益 0.17593 的 4.2%**。

> 所以这一级的结论将是"**训练可以有净收益,但只有 4%**",而不是"训练能显著提升"。
> PLE 的价值目前明确地在**冻结表**里(+0.176 nats),不在训练里。
> 行选择买到的是"训练不再有代价,并且小幅为正",**不是**一个新的能力来源。

**这是预注册的一部分**:不允许跑完之后把这个 4% 说成"显著提升"。
