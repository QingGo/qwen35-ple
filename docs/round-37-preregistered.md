# Round 37：预注册——PLS 监督压缩与稀有 token 子集实验

> 日期：2026-09-03
> 状态：实验前预注册
> 目标：继续用科学范式验证：PLE 信号到底是低秩可提取，还是高维分散？到底帮助长尾知识，还是只帮助局部高频模式？

---

## 1. 实验设计

- 指标：\(\Delta R^2(Y;E\mid H)\)，\(Y=R_t=-\partial L/\partial h_t\)
- 数据：`data/ple-books-160k`，1024 token
- 方法：
  1. **PLS / 监督方向压缩**：用 \(E^\top G\) 的前 r 个右奇异向量作为监督方向；
  2. **稀有 token 子集**：按 token 频率区分稀有/常见上下文，分别计算 \(\Delta R^2\)。

---

## 2. 预注册判读：PLS

### 情形 A：低 r 保持或提升
- r=32/64 时 \(\Delta R^2\) 仍接近或超过全维度。
- 说明：有用信号在**监督低秩子空间**中，应改用 PLS/有监督记忆瓶颈。
- 结论：继续推进低秩 reader。

### 情形 B：需要 r=256+ 才接近全维度
- 说明：信号分散，但监督方向比无监督 PCA 更有效。
- 结论：不能粗暴降维，但可以用 PLS 作为诊断，帮助理解信号结构。

### 情形 C：即使 PLS 也不显著
- 说明：当前 PLE 对 next-token 梯度残差几乎没有可提取信息。
- 结论：应停止当前记忆嫁接方向，或换记忆任务。

---

## 3. 预注册判读：稀有 vs 常见

### 情形 A：稀有 token 正增量更高
- 说明：PLE 确实提供长尾/知识型信息。
- 结论：继续做知识增强是合理的。

### 情形 B：常见 token 正、稀有 token 零/负
- 说明：PLE 主要贡献局部高频 n-gram 模式，不是知识记忆。
- 结论：这是对“知识嫁接”目标的负面证据。

### 情形 C：两者都接近零
- 说明：当前 PLE 对线性 next-token 梯度几乎无信息。
- 结论：停止放大。

---

## 4. 后续（如时间允许）：Oracle MLP

- 若 MLP 的 \(\Delta R^2\) 显著大于线性：需要非线性 reader；
- 若 MLP 与线性接近：当前瓶颈不是函数容量，而是信息量/数据量。
