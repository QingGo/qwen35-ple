# Round 167 设计：怎么"让记忆变得必要"

> 日期：2026-09-13
> 动机：`docs/round-167-synthesis-surprises-and-new-directions.md` §3 D1
> 问题：读出停在秩 1 是因为**秩 1 就够了**。那怎么构造一个"秩 1 不够"的任务？

---

## 1. 先把"必要"定义清楚（三个条件）

秩 1 读出能做的事极为有限：`c_t = out_proj(branch_sum)`，而 `out_proj` 秩 1
意味着 `c_t = s · u` —— **一个标量乘一个固定方向**。
所以"记忆必要"必须同时满足三条，缺一条都可以被秩 1 满足：

| 条件 | 含义 | 若缺失会怎样 |
|---|---|---|
| **A 不可替代** | 该信息**不在** `h_t` 里 | 骨干自己就能算，记忆冗余 → 秩 1 够 |
| **B 多维** | 需要的修正**不是"标量 × 固定向量" | 秩 1 够 |
| **C 依内容** | 修正必须**随被寻址的行变化** | 常数推挤就够（这正是我们现在的解） |

我们现在的任务 A/B/C **全部不满足** —— 所以秩 1 是最优解，读出没有坏。
（`round-167-stage1b-results`：`nozero == prod` 逐位相同、深度只差 10%、
最终 `PR(c_t)` 恰好 1.020 跨越两个中间几何完全不同的 reader。秩由**目标的解**决定。）

---

## 2. 一个关键约束：我们的表是**冻结**的

这推翻了我最先想到的两种设计：

| 想法 | 为什么不行 |
|---|---|
| **合成码本**（N 个 key→value 任意映射，骨干必不会） | 映射不在**冻结的**行里，**任何**读出都取不出来。这需要可训练的表 → 那是 Stage 3 |
| **纯长尾/未见语料** | 若语料对骨干未见，它对**这张表**大概率也未见（表来自 Qwen3.8 的数据），行是噪声 |

**冻结表能提供什么？** 通用文本的 **trigram 统计** —— `round-161` 已证实行里有可恢复的先验
（读出回收约 59% 的计数 trigram top-1）。

**所以对冻结表，"让记忆必要"唯一可做的构造是：
把局部窗口从骨干那里藏起来，只让记忆看得见。**

这恰好就是 Engram 声称的机制 —— *"offloading local pattern reconstruction"* ——
只是我们在一个**卸载真的重要**的制度下测它。

---

## 3. 设计：**窗口遮蔽 + 剂量反应**

### 3.1 构造

对长度为 `L` 的窗口、预测位置 `t+1`：

```text
input_ids    : [... x[t-W] , BLANK × W]        ← 骨干看不到最近 W 个 token
e_t (PLE 行) : 由【真实 ids】计算               ← 记忆照常看得见
target       : x[t+1]
```

实现上只需要在 `run_phase0` 里加一个 `--hide-local-window W`：
先按真实 ids 算 `e_t` 并设进 `model._current_ple_e_t`，
再把 `input_ids` 的最后 W 个位置替换成 BLANK。

`BLANK` 用固定的 filler id（`unk` 或专用 id），序列长度不变，
读出卷积的对齐不变（`round-154` §4.3 的教训：改变序列布局会改因果卷积语义）。

### 3.2 为什么这直接检验理论

* **A 满足**（构造保证）：骨干**看不到**最近 W 个 token。W ≥ 读出的窗口 12 时，
  窗口内容**只能**来自记忆。
* **B/C 由目标决定**：要预测 `x[t+1]`，就必须把"窗口里是什么"编码进 `c_t`。
  不同的窗口 → 不同的下一 token → 需要**多个方向**，秩 1 不够。
* **必要性可测**：`ple-off` 臂给出"没有记忆时"的损失 —— 那是必要性的分母。

### 3.3 剂量反应（关键：把单点变成曲线）

**W ∈ {0, 1, 2, 4, 8, 12}**：

| W | 必要性 | 预期（若理论成立） |
|---|---|---|
| 0 | 0（= 现状） | `PR ≈ 1.02`、`cos(real,shuf) ≈ 0.997` —— 复现基线 |
| 1–4 | 弱 | 三个量开始移动 |
| 8–12 | 强 | `PR` 显著 > 1、`cos(real,shuf)` 显著 < 0.997 |

**剂量反应比单点强得多**：单点"PR 上升了"可以是噪声；
**单调曲线**几乎不可能是别的原因。

三个独立读数（任何一个单独都不够）：

1. **`PR(c_t)`** —— 秩是否上升（`round-165A` 的仪器，已有）
2. **`cos(real, shuf)`** —— 内容是否开始起作用（从 0.9966 掉向 0）
3. **`NEC(W) = loss(ple-off, W) − loss(ple-on, W)`** —— 必要性是否真的被造出来了（**分母检查**）

### 3.4 预注册判据（写在这里，跑之前冻结）

```text
先决条件：NEC(12) 必须显著 > NEC(0)（否则遮蔽没造出必要性 → UNDERPOWERED）

IF PR(12) - PR(0) >= 2  且  cos(12) <= cos(0) - 0.2
    => NECESSITY_UNLOCKS_CONTENT     （塌缩是目标造成的，可修）
ELSE IF PR(12) - PR(0) < 0.5  且  cos(12) >= cos(0) - 0.05
    => COLLAPSE_IS_A_BARRIER         （即使在唯一来源制度下也塌 → 不是目标问题）
ELSE
    => PARTIAL
```

**若出现 `NECESSITY_UNLOCKS_CONTENT`**：论文的核心叙事要改 ——
不是"PLE 无效"，而是**"PLE 在我们选的语料上是冗余的；它一旦必要就能工作"**。
这比现在的负结果强得多，且给出可操作的规定：
**按"骨干测得的无能程度"选语料，而不是按方便选语料。**

**若出现 `COLLAPSE_IS_A_BARRIER`**：这是一个**更强的负结果** ——
连"记忆是唯一来源"都救不回来，说明塌缩是优化/架构壁垒。
那 Stage 3（共训）与 D2（rank-promoting 目标）就是仅剩的路。

## 4. 诚实的边界（这套设计**不能**证明什么）

1. **遮蔽是人工的**。它证明的是"记忆在必要时能否承载内容"，
   **不是**"PLE 在标准 LM 下有增益"。后者仍然被 `round-157` §1.1 的界限制
   （那界只覆盖上下文条件化知识，不覆盖这里的局部窗口重构）。
2. **W ≥ 12 时任务变得非自然**：真实 LM 里骨干总能看见窗口。
   所以这是**机制实验**，不是产品实验。价值在于**定位能力边界**并给出尺子。
3. **不改变冻结表**。若 `NECESSITY_UNLOCKS_CONTENT`，我们证明了**读出**能承载内容；
   但**表里有多少内容**仍是另一个问题（`round-161` 的 ~59% 回收率）。

## 5. 实施清单

```text
[1] run_phase0.py 加 --hide-local-window W（默认 0，纯新增）
       - e_t 用真实 ids 算（现有逻辑不变）
       - input_ids 末 W 位替换为 BLANK
       - 记录 W 与 NEC 到输出 JSON
[2] run_phase0.py 加 --local-window-blank-id（默认 unk 或 0）
[3] 六个 W × {real, ple-off} 的训练，0.8B，短（各 500 步）
       - 复用 Stage 2.2 的内存闸门并发（实测 93% 利用率）
[4] 每个 W 跑一次 provenance（offset 0 与 12）拿 PR 与 cos(real,shuf)
[5] 分析脚本按 §3.4 判据出结论
```

**成本**：6 个 W × 2 臂 = 12 次短训练 + 12 次 provenance。
训练各约 4 分钟，provenance 各约 4 分钟；**2 路并发下约 1 小时**。

**先做一个 W=12 的冒烟**（确认 NEC 真的被造出来）再铺开六个点——
**如果先决条件不成立，整个设计就白做**，这是必须最先验证的一步。

---

## 6. 与另一条正交的线

上面的构造受"冻结表"限制。**若表可训练**，就能做我最初想做的
**合成码本**（N 个任意 key→value，骨干必不会，必要性 = 1/N）：

* 必要性**可证明**（无记忆 = 随机猜）
* 预测更锐利：**`PR(c_t)` 应随 N 增长**（要输出 N 个不同 token 就需要 ≥ rank N）

那是 **Stage 3（共训）** 的旗舰实验，前提是表可训练。
两条线合起来给出一张完整的图：

| 表状态 | "必要"怎么造 | 检验什么 |
|---|---|---|
| **冻结**（现在） | 隐藏局部窗口 | 读出**能否**承载内容 |
| **可训练**（Stage 3） | 合成码本 / 长尾语料 | 表**能否**存下内容，以及 SKU 是否有价值 |

**先做冻结这条**：它便宜、不需要改训练配方，而且**无论正负都改变结论**——
正：读出可修，叙事翻正；负：塌缩是壁垒，只剩共训一条路。
