# Round 157: 为什么这条 graft 是「先验通道」而不是「知识通道」—— 一个能解释全部否证的结构论证

> 前置：round-152（G1 不通过）、round-153（目标精确化）、round-155（G0 假阳性拆解）、
> round-156（格式 vs 知识、两个指标 bug）。

---

## 0. 一句话

**五次独立否证不是五个偶然，而是同一个结构事实的五种表现：**
哈希索引的「每 n-gram 常量向量 + 小适配器读出」在结构上只能承载
**给定最近 2–3 个 token 的续写先验**，承载不了**以全上下文为条件的知识**。
我们一直在用"知识"的尺子量一个"先验"器件。

> **§1.1 补记：这条后来被证明是硬上界，不是经验观察。**
> `e_t` 是前三个 token 的确定性函数，故 `I(e_t ; token[t+1]) ≤ I(trigram ; token[t+1])`，
> 与 reader 的容量和训练量无关。详见 §1.1。

---

## 1. 结构论证

我们的表是这样被读出来的（`OfficialSourceQwenReader`）：

```text
rowids_for_seq  16 个头（8 个 2-gram + 8 个 3-gram），每头取 1 行 160 维 → e_t ∈ R^2560
key             key_proj(e_t)      ← 冻结（官方源空间）
query           query_bridge(h_t)  ← 可训练，唯一的上下文入口
gate            sigmoid(f(key·query))  每分支一个标量（共 4 个分支）
value           value_proj(e_t)    ← 冻结；对同一 n-gram 是常量
                gated → RMSNorm → 深度可分离因果卷积 → 4 分支求和 → out_proj → h
```

关键在两点：

1. **同一个 n-gram 取回的行是常量**，与上下文无关。上下文只能通过
   **4 个标量门**（每分支一个）和一段**短因果卷积**影响读出。
2. 从"n-gram 身份"到"隐藏贡献"的映射由 `out_proj ∘ value_proj ∘ 门 ∘ 卷积` 学到，
   参数量约 15M，且**对全部 3.2 亿行共享**。

于是这个映射只能是一个**平滑、低复杂度**的函数。它能实现的是
"看到这个 bigram/trigram，就往某个方向推一推"——即**续写先验**；
它无法实现"根据这段长文，取出某个具体事实"。后者需要的是
**按查询取回不同内容**的通道，而这里取回的内容由 n-gram 哈希唯一决定，与查询无关。

> 换句话说：**query 只能决定"用不用"，不能决定"用什么"。**
> 表是常量，读出是低保真度旋钮。

## 1.1 补记（Round 157b）：这不是论证，是**可证明的上界**

上面 §1 还是"读出带宽受限"的论证。后来在 `src/qwen35_ple/ple_hash.py::PleSpec.rowids_for_seq`
里读到了一件更强的事，并且已从源码逐行核实：

```python
shifted = [self._shift_right_ignore_eos(hist, shift) for shift in range(PLE_NGRAM_SIZE)]
for ngram_order, shift_range in ((2, 0), (3, PLE_HEADS_PER_NGRAM)):
    mixed = (shifted[0][pos] * self.multipliers[0]) & _U64_MASK
    for shifted_row, multiplier in zip(shifted[1:ngram_order], self.multipliers[1:]):
        mixed ^= (shifted_row[pos] * multiplier) & _U64_MASK
```

`shift = 0, 1, 2` 分别取到 `token[t]`、`token[t-1]`、`token[t-2]`。**16 个头全部只依赖
(t-2, t-1, t) 这三个 token**，因此

```text
e_t = f(token[t-2], token[t-1], token[t])        （确定性函数）
⟹  I(e_t ; token[t+1]) ≤ I( (token[t-2],token[t-1],token[t]) ; token[t+1] )
```

由数据处理不等式，这条上界**与 reader 的深度、宽度、线性与否、训练量全都无关**。
不是"我们的 reader 不够好"，而是**表里根本不可能装下超出 trigram 的未来信息**。

三点后果：

1. **"外部记忆注入知识"在这个架构下是封闭的。** 不是五次实验没做对，是设计上不可能。
   上下文条件化的事实取回需要"按查询取回不同内容"，而取回键只有 trigram。
2. **它仍可以是一个好的 trigram 记忆。** Qwen3.8 见过的文本远超我们那 100 万 token，
   所以表里可能存着**估计得更好**的 trigram 后验。这是它唯一还可能赢的地方。
3. **因此唯一有意义的对手是同存储的计数 n-gram 模型**，而不是"不注入"。
   §4 说的最大缺口，现在从"方法论建议"变成了"唯一正确的对照"。

> 这也修正了本文原先的措辞：**天花板是表的属性，不只是 reader 的属性。**

## 2. 它一次解释了全部五次否证

| 已否证 | 结构论证的预测 |
|---|---|
| 冻结嫁接注入知识（round 148/149） | 通道无法做上下文条件取回 → 无知识增益 ✅ |
| reader 容量/源空间对齐是瓶颈（148-B） | 加大适配器加不出缺失的上下文条件 → 不是瓶颈 ✅ |
| oracle routing 线性可学（oracle probe） | reader 不是"路由器"，是常量读出 → 学不出路由 ✅ |
| 数据规模（data scaling） | 瓶颈在通道结构，不在数据量 ✅ |
| LoRA 共适应解锁 PLE（round 152 G1） | 共适应救回"不崩"，但改不了取回带宽 → 内容效应仍为零 ✅ |
| G0 4B（hidden 精确对齐源空间） | 对齐解决不了结构问题 → 只有格式效应 ✅ |

外加两个新证据正好落在预测上：

* **PLE 首先改的是格式**（round-156）：零注入时 4B 不守 raw 协议、吐 chat 脚手架；
  注入后（**real 与乱序行皆然**）被压回 raw 续写模式。这正是"续写先验"该有的样子。
* **乱序行会破坏生成**（round-156：TriviaQA 52.8% 空串）：先验错了，续写就崩。

## 3. 这对终极目标意味着什么

原目标：「纯 PLE 嫁接，通过少量训练显著提升 0.8B 通用性能」。

按现有证据，**这条通道做不到**，而且不是调参能解决的。两个可选方向：

**方向 A：接受它是先验，换一个它天然擅长的任务族。**
"给定最近 2–3 个 token 的续写"是它的强项所在：逐字续写、罕见实体、近重复文本、
长尾 n-gram。**在这些任务上，"同预算纯参数"才是公平对手** —— 因为长尾 n-gram
存在权重里极其昂贵、存在表里极其便宜。这是外部记忆唯一真正的信息论优势。

**方向 B：换读出架构。**
如果确实要"知识"，瓶颈是**用学习到的常量向量做读出**。换成
**显式计数通道**（suffix array / infini-gram 式：直接给出下一 token 的分布，
再以 log-prob 相加）就绕开了这个瓶颈 —— 读出不再是一个要学的平滑函数，
而是直接把分布交出来。本仓库已有 `run_ngm_baseline.py` / `run_knn_lm_baseline.py`，
这条线有现成地基。

**两者都需要先补一个我们从未做过的对照。**

## 4. 最大的缺口：我们从来没和「同预算纯参数」比过

至今所有对比都是 **PLE vs 不注入 PLE**。但表是 ~51GB 的存储：
公平的对手不是"什么都没有"，而是**同样 51GB 花在参数或检索上**。
没有这个对照，"PLE 有用/没用"根本没有参照系 —— 这是本项目最大的方法论缺口，
也是 round-153 把目标改写为**"找出外部 n-gram 记忆优于同预算纯参数方案的区间"**的原因。

## 6. 结论

* 我们不是"失败了五次"，而是**收敛到了一个可陈述的结构命题**，
  并且它给出了明确的任务边界（先验类任务有戏、知识类任务没戏）与明确的下一个实验。
* 目标从"证明外部记忆能提升 0.8B"→"找出外部 n-gram 记忆相对同预算纯参数占优的区间"
  → 现在可以更精确：**"在长尾/逐字续写这类先验敏感任务上，量化外部记忆的存储-算力优势区间"**。
* 如果这条也否证，那么诚实的落点是 round-153 已经写好的：
  **把 PLE 定位为"格式先验 + 可热插拔的领域先验"，通用能力交给参数与数据。**

## 7. 更正（Round 159）：本文的界是对的，但从它推出的结论**过重**

有人问了一个本文必须回答的问题：**既然这条通道在数学上做不到，那 Qwen3.8-Flash-Next、
DeepSeek-V4.1-Flash、DeepSeek Engram 为什么能做到？**

查 `docs/round-147-engram-lineage-comparison.md`（四系统逐项对照）后，本文需要两处更正。

### 7.1 界本身没问题，而且比本文说的更普适

`{2,3}` 阶**不是本仓库的简化，是官方 Qwen 设计**；Engram-27B 同为 `{2,3}`，
V4.1 为 `{2,3,4}`。三家的共同原语是"对 token x_t 取最近 n-1 个 token 的后缀 n-gram 哈希"，
所以 §1.1 的上界**对三家同样成立**（V4.1 是 4-gram 界）。界限制的是**寻址方式**，
不是某一家的实现。

### 7.2 但"这条通道不值钱"是**没有**被证明的

§3/§4 把"通道是短窗口先验"顺势读成了"所以它没什么用"，这是过度声称：

1. **界限制的是信息量，不是有用性。** 骨干权重是训练语料的有损压缩，低频 n-gram 统计
   正是被压掉的部分 —— 表补的正是这个。而 0.8B 的权重比 6B active 丢得**更多**，
   原则上小模型应该**更**受益。
2. **≈4.94 nat 不是通道天花板。** 它是从 **1M token** 学习曲线外推的，而原版记忆由
   **数万亿 token** 构建；真实 trigram 后验远好于此。"最多值 0.40 nat"**只在本套语料+评测下成立**。
3. **本文的全部否证，否证的都是同一个配置**：**冻结的表 + 从未学过使用记忆的主干**。
   而原版三家：表**可训练**（Adam 5×LR / momentum+Sinkhorn）、主干与记忆**联合训练**、
   记忆:算力在 1.4×–24.5×（我们是 **64×**）、无跨空间桥、gate 有选择性。
   我们的 SFT reader gate 饱和常开（0.77–0.98）= 恒开注入 = 噪声。

### 7.3 修正后的表述

* ✅ 成立：**token n-gram 哈希寻址的通道不可能承载上下文条件化知识**；
  我们此前的知识型探针（QA / oracle routing / rare-entity）都在问错的问题。
* ❌ 不成立："Engram 设计不成立"或"外部记忆没用"。**这两件事没有被证明。**
* ➡️ 因此"不要再做冻结嫁接的 QA 消融"是对的，但**不能**顺势停止整条线：
  原版验证过的配置（可训练的表 + 学过路由的主干 + 长尾语言建模目标）**尚未测过**。

要绕开 §1.1 的界，唯一的办法是换成**查询相关寻址**（kNN-LM / RETRO 式真检索），
而不是继续在 token n-gram 哈希上做文章。
