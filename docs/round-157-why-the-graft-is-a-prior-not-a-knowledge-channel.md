# Round 157: 为什么这条 graft 是「先验通道」而不是「知识通道」—— 一个能解释全部否证的结构论证

> 前置：round-152（G1 不通过）、round-153（目标精确化）、round-155（G0 假阳性拆解）、
> round-156（格式 vs 知识、两个指标 bug）。

---

## 0. 一句话

**五次独立否证不是五个偶然，而是同一个结构事实的五种表现：**
哈希索引的「每 n-gram 常量向量 + 小适配器读出」在结构上只能承载
**给定最近 2–3 个 token 的续写先验**，承载不了**以全上下文为条件的知识**。
我们一直在用"知识"的尺子量一个"先验"器件。

---

## 1. 结构论证

我们的表是这样被读出来的（`OfficialSourceQwenReader`）：

```text
rowids_for_seq  16 个头（8 个 2-gram + 8 个 3-gram），每头取 1 行 160 维 → e_t ∈ R^2560
key             key_proj(e_t)      ← 冻结（官方源空间）
query           query_bridge(h_t)  ← 可训练，唯一的上下文入口
gate            sigmoid(f(key·query))  每分支一个标量（共 4 个分支）
value           value_proj(e_t)    ← 冻结；对同一 n-gram 是常量
                gated → RMSNorm → 深度可分离因果卷积 → 4 分支求和 → out_proj → h
```

关键在两点：

1. **同一个 n-gram 取回的行是常量**，与上下文无关。上下文只能通过
   **4 个标量门**（每分支一个）和一段**短因果卷积**影响读出。
2. 从"n-gram 身份"到"隐藏贡献"的映射由 `out_proj ∘ value_proj ∘ 门 ∘ 卷积` 学到，
   参数量约 15M，且**对全部 3.2 亿行共享**。

于是这个映射只能是一个**平滑、低复杂度**的函数。它能实现的是
"看到这个 bigram/trigram，就往某个方向推一推"——即**续写先验**；
它无法实现"根据这段长文，取出某个具体事实"。后者需要的是
**按查询取回不同内容**的通道，而这里取回的内容由 n-gram 哈希唯一决定，与查询无关。

> 换句话说：**query 只能决定"用不用"，不能决定"用什么"。**
> 表是常量，读出是低保真度旋钮。

---

## 2. 它一次解释了全部五次否证

| 已否证 | 结构论证的预测 |
|---|---|
| 冻结嫁接注入知识（round 148/149） | 通道无法做上下文条件取回 → 无知识增益 ✅ |
| reader 容量/源空间对齐是瓶颈（148-B） | 加大适配器加不出缺失的上下文条件 → 不是瓶颈 ✅ |
| oracle routing 线性可学（oracle probe） | reader 不是"路由器"，是常量读出 → 学不出路由 ✅ |
| 数据规模（data scaling） | 瓶颈在通道结构，不在数据量 ✅ |
| LoRA 共适应解锁 PLE（round 152 G1） | 共适应救回"不崩"，但改不了取回带宽 → 内容效应仍为零 ✅ |
| G0 4B（hidden 精确对齐源空间） | 对齐解决不了结构问题 → 只有格式效应 ✅ |

外加两个新证据正好落在预测上：

* **PLE 首先改的是格式**（round-156）：零注入时 4B 不守 raw 协议、吐 chat 脚手架；
  注入后（**real 与乱序行皆然**）被压回 raw 续写模式。这正是"续写先验"该有的样子。
* **乱序行会破坏生成**（round-156：TriviaQA 52.8% 空串）：先验错了，续写就崩。

## 3. 这对终极目标意味着什么

原目标：「纯 PLE 嫁接，通过少量训练显著提升 0.8B 通用性能」。

按现有证据，**这条通道做不到**，而且不是调参能解决的。两个可选方向：

**方向 A：接受它是先验，换一个它天然擅长的任务族。**
"给定最近 2–3 个 token 的续写"是它的强项所在：逐字续写、罕见实体、近重复文本、
长尾 n-gram。**在这些任务上，"同预算纯参数"才是公平对手** —— 因为长尾 n-gram
存在权重里极其昂贵、存在表里极其便宜。这是外部记忆唯一真正的信息论优势。

**方向 B：换读出架构。**
如果确实要"知识"，瓶颈是**用学习到的常量向量做读出**。换成
**显式计数通道**（suffix array / infini-gram 式：直接给出下一 token 的分布，
再以 log-prob 相加）就绕开了这个瓶颈 —— 读出不再是一个要学的平滑函数，
而是直接把分布交出来。本仓库已有 `run_ngm_baseline.py` / `run_knn_lm_baseline.py`，
这条线有现成地基。

**两者都需要先补一个我们从未做过的对照。**

---

## 4. 最大的缺口：我们从来没和「同预算纯参数」比过

至今所有对比都是 **PLE vs 不注入 PLE**。但表是 ~51GB 的存储：
公平的对手不是"什么都没有"，而是**同样 51GB 花在参数或检索上**。
没有这个对照，"PLE 有用/没用"根本没有参照系 —— 这是本项目最大的方法论缺口，
也是 round-153 把目标改写为**"找出外部 n-gram 记忆优于同预算纯参数方案的区间"**的原因。

## 6. 结论

* 我们不是"失败了五次"，而是**收敛到了一个可陈述的结构命题**，
  并且它给出了明确的任务边界（先验类任务有戏、知识类任务没戏）与明确的下一个实验。
* 目标从"证明外部记忆能提升 0.8B"→"找出外部 n-gram 记忆相对同预算纯参数占优的区间"
  → 现在可以更精确：**"在长尾/逐字续写这类先验敏感任务上，量化外部记忆的存储-算力优势区间"**。
* 如果这条也否证，那么诚实的落点是 round-153 已经写好的：
  **把 PLE 定位为"格式先验 + 可热插拔的领域先验"，通用能力交给参数与数据。**
