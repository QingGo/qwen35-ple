# Round 106：资源有限现状下的下一步方向

> 日期：2026-09-06  
> 状态：基于顶刊差距分析和当前资源约束的系统性取舍  
> 原则：**用最小的算力、最大的信息增益，先回答“是否值得继续”和“论文卖点是什么”，再扩展。**

---

## 1. 当前资源约束

| 资源 | 现状 |
|---|---|
| GPU | 单张 GTX1070 8GB |
| 数据 | 本地只有合成/局部小数据，无官方大基准 |
| 模型 | Qwen3.5-0.8B，小模型 |
| 训练 | 只能小步数 LoRA/QLoRA/MoRA |
| 推理 | GPU/CPU 均可，但 CPU 目标 100 tok/s 未验证 |
| 时间/人力 | 有限，不能做大规模预训练或 RL |
| 已有资产 | PLE 工具、per-task 校准、Purified OPSD 数据、正式风格基准、已有 MoRA/QLoRA adapter |

---

## 2. 决策原则

> 在有限资源下，不做“全面铺开”，而是：
> 1. 先做 **低成本、高信息** 实验；
> 2. 先证明 **核心创新是否不可替代**；
> 3. 先形成 **可发表的最小证据闭环**；
> 4. 产品化只做“能证明低资源价值”的部分。

---

## 3. 下一步方向：按信息/算力比排序

### 方向 A：把 Purified OPSD 做稳（最高性价比）

理由：

- 已有 138 条验证数据；
- 80 步 MoRA 已跑通；
- 多 seed 成本低；
- 直接回应顶刊“统计显著”和“可复现”要求。

具体：

1. Purified MoRA-80/160，seed 0/1/2；
2. 对比 LoRA / QLoRA / MoRA；
3. 在正式风格基准上报告 mean±std、CI、paired test。

预计 GPU 时间：几小时。

---

### 方向 B：证明 PLE 的不可替代性（最高审稿价值）

这是当前最大风险。低成本做法：

1. 在现有真实局部任务上增加：
   - BM25 基线；
   - 纯 n-gram 基线；
   - kNN-LM 或至少 kNN top-k 基线；
   - 无记忆 base；
2. 对 code/name/number 分别报告：
   - PLE vs BM25；
   - PLE vs n-gram；
   - PLE vs dense；
3. 如果 PLE 无法显著超越这些基线：
   - 论文转向“系统/边界/负结果”；
   - 或把创新重心转移到 Purified OPSD + 多源 router + 低资源部署。

---

### 方向 C：联合系统评测（低成本但关键）

1. 用已有 adapter 和 PLE 配置跑：
   - base；
   - +PLE；
   - +RAG；
   - +Purified MoRA；
   - +all；
2. 在正式风格基准 + PLE 局部任务上；
3. 3–5 seed；
4. 输出一张主表。

这能回答：

> 各组件是互补、冗余，还是相互抵消？

---

### 方向 D：统计严谨性升级

成本低，但容易被审稿人挑刺。

- 5 seeds；
- bootstrap 95% CI；
- paired permutation test；
- 至少在主任务报告 effect size。

---

### 方向 E：理论验证

- 验证支撑集质量定理：
  - 画出 \(q_\beta(S)\) vs \(p_t(S)\)；
  - 比较全局校准 vs per-task 校准；
- 验证给定任务下 \(E[\log p_m-\log p_b]\) 的真实分布；
- 验证 Hedge router 在验证集上的 regret；
- 这些实验不依赖大 GPU。

---

### 方向 F：CPU 产品化证据

- 运行 CPU benchmark；
- 尝试 int8 / GGUF 量化；
- 报告：
  - tokens/sec；
  - 内存；
  - 延迟；
  - 量化后质量损失。

这能把“低资源”从口号变成证据。

---

### 方向 G：强基线中的“低成本但高影响”

如果可以获取/构造：

- kNN-LM 小规模实现；
- BM25-only；
- dense-only；
- 纯 n-gram LM。

这些不需要大训练，只需要推理和现有语料。

---

## 4. 不建议现在做的事

- 大规模预训练；
- 全参微调；
- RL / RLVR；
- 大 teacher 蒸馏；
- 多 GPU / 大模型；
- 盲目扩数据；
- 在没有 PLE 不可替代性证据前，把 PLE 当论文主卖点。

---

## 5. 资源分配建议

| 阶段 | 做什么 | 预计成本 |
|---|---|---|
| 1 | Purified OPSD 多 seed + 统计 | 低-中 |
| 2 | PLE vs BM25/n-gram/kNN 不可替代性 | 低 |
| 3 | 联合系统评测 | 低-中 |
| 4 | 理论验证 + 误差分析 | 低 |
| 5 | CPU 100 tok/s + 量化 | 中 |
| 6 | 可复现 manifest / artifact | 低 |
| 7 | 真实 HumanEval/GSM8K 子集（如能获取） | 中 |

---

## 6. 关键决策点

### 决策 1：PLE 是否继续作为主创新？
- 如果 PLE 在 code/name 上显著超过 BM25/n-gram/kNN：
  → 继续主创新，写系统论文。
- 如果不显著：
  → 转为“可审计外部记忆的边界研究”或“低资源系统论文”，主卖点改为 Purified OPSD + 部署。

### 决策 2：Purified OPSD 是否值得作为主能力来源？
- 如果多 seed 在正式风格基准稳定正提升：
  → 把 Purified OPSD 作为第二创新点。
- 如果不稳定：
  → 回到数据/验证过滤。

### 决策 3：是否先做产品化？
- 如果 CPU 100 tok/s 可达且精度可接受：
  → 产品化可成为论文的“低资源落地”部分。
- 如果不可达：
  → 先不做产品化，专注科学证据。

---

## 7. 结论

> 资源有限时，下一步不是“再做一个大实验”，而是：
> 1. **把已有小实验做多 seed、做统计、做基线；**
> 2. **用最低成本回答“PLE 是否不可替代”；**
> 3. **把 Purified OPSD 作为可复现的能力提升证据；**
> 4. **最后用 CPU 100 tok/s 和量化证明低资源价值。**
>
> 这样我们才能在有限资源下，最大化论文/产品的成功概率。
