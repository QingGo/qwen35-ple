## 0. 预注册（本节在任何数字产生之前写入，之后不得改写）

### 0.1 被检验的断言

**主断言（要打死的那个）**：把检索到的记忆注入残差流，起的是**格式 / 协议先验**的作用。
在回答位置，寻址窗口只携带位置/格式信息，所以「格式」是记忆唯一能加的东西。
具体：round-156 在 4B 上观察到，**零注入**时模型吐对话脚手架
`\n\n<think>\n\n</think>\n\n...`，而**注入时（真行与乱序行皆然）**吐简洁的 raw 续写 ` yes`。

**竞争解释（必须能排除）**：这不是先验，而是「**层 2 上一发足够大的扰动打断了模型的对话模板**」。
在这个读法下记忆内容无关，没有格式先验，只有伪影。

### 0.2 六臂

同一冻结骨干、同一提示、同一读出架构、同一训练预算：

| 臂 | 训练行来源 | 评测行 |
|---|---|---|
| 1 `wiki` | PURE_WIKI | 真行 |
| 2 `code` | PURE_CODE | 真行 |
| 3 `stem` | PURE_STEM | 真行 |
| 4 `wiki-shuf` | PURE_WIKI | **乱序行**（同分布、等幅度，内容错配） |
| 5 `ple-off` | 读出器在位、贡献恒为 0 | — |
| 6 `no-reader` | 无读出器 | — |

决定性对比是 **1 vs 2 vs 3**。

### 0.3 预注册预测

* **P1（内容相关先验成立）**：臂 1/2/3 的**格式分布彼此不同**，且方向与各自训练语料一致
  （CODE 臂升高代码类续写/代码栅栏，WIKI 臂升高散文，STEM 臂升高公式/推理式续写）。
* **P2（扰动伪影成立）**：臂 1/2/3 **彼此不可区分**，且与臂 4 不可区分；三者（四者）
  一致地与臂 5/6 不同。
* **P3（无论哪种读法）**：臂 5 与臂 6 **应当彼此接近**（`--ple-off` 与无读出器在数学上
  都注入 0；差异只能来自实现路径）。
* **P4（内容依赖的词汇证据）**：若 P1 成立，则各臂生成文本的**领域词法指纹**
  （代码标记率 / 数学标记率 / 散文标记率）也应随训练语料移动；若 P2 成立，则不动。

### 0.4 否证条款（FALSIFICATION CLAUSE）

**若臂 1/2/3 彼此不可区分，则我的「格式先验」读法是错的**；诚实的结论是
「**注入扰动了模板，内容无关**」。这是一个正当且有价值的结果，**必须照实报告，不得软化**。

### 0.4b 机械判决规则（同样在任何数字之前写定）

为避免事后挪动标准，判决由一个**固定算式**给出，参数全部来自数据本身：

1. **噪声地板**：臂 5（`ple-off`）与臂 6（`no-reader`）在数学上是**同一机制**
   （注入恒为 0）。它们之间的差就是本管线的**实现噪声地板**，
   记为 `F_scaffold`（脚手架率的逐条配对 |Δ|）与 `F_tv`（标签分布的 TV 距离）。
2. **内容效应量**：臂 1/2/3 两两之间脚手架率逐条配对 |Δ| 的最大值记为 `S_123`，
   其配对 SEM 记为 `SE_123`；标签分布 TV 距离的最大值记为 `S_tv`。
3. **判决**：
   * `S_123 > max(F_scaffold, 3·SE_123)` → **CONTENT_DEPENDENT**；
   * 否则 → **PERTURBATION_ARTIFACT**。
4. **co-primary 格式指纹**（同样在正式臂数字之前写定）：粗分类法可能对真实存在的格式移动**不敏感**——
   `'\n\nYes'` 与 `' Yes'` 在分类法下**都是** `raw_continuation/terse`，而这正是 round-156 头条
   （`\n\n<think>…` vs ` yes`）所在的那一层。因此同时用四个更细的**格式**描述子，
   各按同一「噪声地板 vs 1/2/3 内部最大」规则判一次：
   * `tv_label_dist`：分类法标签分布 TV；
   * `tv_prefix_dist`：**前导面**（`newline_lead` / `space_lead` / `no_lead` / `empty`）分布 TV；
   * `tv_joint_dist`：`label × 前导面` 联合分布 TV（**副判决**用这个）；
   * `tv_first_token_dist`：**首个生成 token id** 的分布 TV——比分类法更细，且正是
     round-156 指标 bug #2 讨论的那一层（` yes`=9542 vs `yes`=9405）。
   另报 `prefix_newline_lead` 的逐条配对 |Δ|（零注入的 `\n\n…` 形状）。
   > 这些描述子全部只描述**格式**（前导空白结构、首个 token），不描述**内容**；
   > 内容相关的证据另由领域词法指纹与 §3 的逐条阅读给出。
5. 同时报告「注入（1/2/3/4）vs 零注入（5/6）」的逐条配对差、McNemar 精确 p 与 TV，
   以确认**格式移动本身是否存在**（若不存在，本轮的诚实头条就是「该骨干上效应不复现」）。
6. 方向性预测（§0.3 P4）以**逐条配对、单侧 p** 检验：`code` 臂的代码标记 > `wiki` 臂、
   `stem` 臂的数学标记 > `wiki` 臂、`wiki` 臂的散文标记 > `code` 臂。
7. **操纵强度检查**（`scripts/run_round162_reader_crosseval.sh`）：三个读出器在三个语料的
   held-out 窗口上交叉评测 next-token loss。**若读出器没有在自己的语料上更低，则「内容无关」的
   结论不可解释**（可能是操纵没生效，而非内容不重要）。这一条是 null 结果的可解释性前提。

> 已知保守性：`F_scaffold` 若恰为 0（5/6 逐条完全相同），门槛退化为 `3·SE_123`，
> 仍能挡住「靠 n 制造显著性」的做法。
>
> 时序声明：§0.4b 写于任何**正式臂**数字产生之前；此前只跑过一次 12 条 / 12 步的**管线冒烟**
> （用于验证六臂脚本可运行、批大小不改变贪心输出）。冒烟数字不进入任何结论。

### 0.5 幅度控制（不可谈判，否则比较作废）* 逐臂报告**注入贡献范数 / 注入层骨干隐状态范数**的比值。实现方式：给 `run_phase0.py` 加了一个
  **纯新增、默认关闭**的开关 `--qa-norm-stats`，它在每个解码步记录注入层上
  `‖contribution‖` 与 `‖hidden‖` 在**答案前一位**的比值（`qa_norm_ratio_mean / _median / _p90 /
  _of_means`）并写进 summary。默认关闭保证历史轮次逐位可比。
  （`models/` 全为 `--ple-off` 与 `no-reader` 时注入恒为 0，这些键不出现，即比值 = 0。）
* 用 `scripts/audit_reader_checkpoints.py` 检查：冻结张量跨臂**位级一致**、适配器**确实移动**、
  跨臂适配器范数比。
* **若臂间范数比超过 ~3×，比较被混淆，必须照实说明，而不是报告内容效应。**

### 0.6 测量口径（用解析器，不用字符串启发式）

本项目已被指标定义坑过两次（子串 EM 把脚手架臂虚高 33 点；gold NLL 在给模型不会吐的 token 打分）。
因此本轮：

* 逐条生成按**显式分类法**分类（`scripts/classify_format.py`，规则见 §2），报告**每臂完整分布**，不只报单一比率；
* 直接使用 `run_phase0.py` 已有的 `qa_fmt_scaffold_rate` / `qa_fmt_empty_rate` / `qa_fmt_distinct_rate` /
  `qa_fmt_boolq_yes_rate` 与 token 级 EM（**本报告确实使用了它们**，见 §5）；
* n 足够大，使分布移动能与噪声区分；报告 **n 与逐条配对比较 + SEM**，不只报边际率。

## 1. 设计理由（方法）

### 1.1 提示集的选择，以及为什么格式是「欠定」的

使用 round-156 同一套 **standard 1500**（`data/qa-standard/eval.jsonl`，BoolQ/TriviaQA/NQ 各 500）
与同一 raw 协议：

```text
Question: {question}\nAnswer:
Question: {question}\nAnswer with one word, Yes or No:      (BoolQ)
```

理由：**这是格式确实欠定的那个协议**。它是一条「补全式」提示，不在模型的对话分布里，
因此模型对它的续写存在**至少两个都合法的模式**——(a) 直接续写答案，(b) 从对话先验"逃逸"成
chat 脚手架（`<think>` / 角色标记）。round-156 正是在这里看到零注入走 (b)、注入走 (a)。
选任何**已经写死输出格式**的提示（如严格的 JSON-only 指令）都只会测到指令跟随，不是先验。

为把这一点做实，逐任务分开报告：TriviaQA / NQ 的提示只有 `Answer:`，是**真正欠定**的；
BoolQ 的提示含 "Answer with one word"，若脚手架臂仍然违反它，说明该指令在实践中并不约束格式。
（round-156 的 gg0-nople 臂正是如此：吐 `<think>` 并幻觉新轮次。）

### 1.2 骨干与精度

**Qwen3.5-0.8B，float32，层 2 注入。** 理由：

* 6 臂 × (训练 + 评测) 在 0.8B 上是可承受的；4B 上同样规模会显著更贵。
* round-156 的格式效应是在 **4B + bfloat16** 上看到的。因此本实验**首先**要回答的是
  「在 0.8B 上这个效应**是否复现**」。若不复现，那本身就是发现（见 §7），
  **不得为了造出效应而去搜配置**。
* 精度选 fp32：0.8B 在 24GB 卡上 fp32 完全放得下，且避免 bf16 归一化/归约带来的
  逐位不确定性——本轮的比较是**跨臂**的，臂间任何数值噪声都应以最小化优先。
  （4B 路径必须 bf16 才能放进 24GB，这是 round-152 的约束，不是本轮的约束。）

### 1.3 唯一变量

除语料外全部相同：`--reader official --layer 2 --bridge-mlp --out-mlp`、
steps=500、seq-len=128、lr=1e-4、seed=0、同一 `--qa-sft-*` 配方、同一评测提示。
**臂 1/2/3 之间唯一改变的是 `--tokens-npy`**（即读出器在训练时看到的是哪一族 n-gram 行）。

> 语义澄清（重要）：「训练语料」改变的**不是评测时取回哪些行**（评测时行由提示 token 决定，
> 各臂相同），而是**读出器把这种 n-gram 行解释成什么**。因此 1/2/3 的对比恰好是
> 「同一张表、同一批行、不同的读出先验」——这正是「记忆内容是否决定注入语义」的最干净形式。

### 1.4 次要 regime：去掉 QA-SFT 混合

主实验沿用 round-152 的读出器配方（`--qa-sft-weight 0.5`，即在 `data/qa-standard/train.jsonl`
上做答案-only SFT 与语料窗口 1:1 混合），以便与 round-156 直接可比。但该配方有一个**自带的稀释**：
每一步有 50% 的概率抽到**各臂完全相同**的 QA 项，也就是说「语料」这一操纵只作用在一半的训练步上，
而且 QA 混合本身就在教读出器「在答案位置吐答案」——这**恰好是被测的那个格式先验**。

因此本轮**额外**跑一个 `NO_SFT=1` 的 regime（读出器**只在语料窗口上**训练，
`--qa-sft-weight 0`），作为**次要 regime** 报告。两个 regime 都报，谁的结论都不许单独冒充全部。

### 1.5 基础设施偏离与一个被发现的指标 bug（如实记录）

1. **锁**：/tmp/qwen35_heavy.lock 曾被一个 sibling 的 CPU-only 任务（round-160 n-gram 基准，
   `nvidia-smi --query-compute-apps` 为空、GPU 0%）持有。本队列**先按规矩等待** 3600 s，
   若仍未释放则**记录后放弃锁继续**（因为本队列只需 GPU）。实际等待时间为 0 s（sibling 恰在此时结束），
   所以本轮**没有**发生并发争用；这一条只是把机制写清楚。
2. **指标 bug（本轮发现并修复）**：`scripts/run_phase0.py` 的 `_qa_gold_nll` 在 commit
   `f1685cf`（round-157b）被 `for group in groups` 重构时**缩进错位**——`for offset ...` 的循环体
   （`attention_mask = ...` 起的 57 行）少缩进一级，于是**每个 variant 组只评了最后一个 chunk**。
   证据：所有带 `nll_spaced` 的产物都报 `qa_gold.metrics.qa_n = 4.0`（`--qa-batch-size 8`），
   而不是 1500；若用 round-152 的 `--qa-batch-size 1` 则**只评 1 条**。
   round-152/g0 的 gold NLL 早于该 commit，不受影响。已修复并**跨 batch 1/8/16 验证逐位一致**
   （24 条：raw 15.9021 / spaced 9.8808，n=24）。
   → 本报告**不**用 gold NLL 支持任何结论；它只作为次要格式敏感度指标出现，且六个臂的
   gold NLL 一律用**修复后**的脚本离线重算，保证同口径。

## 2. 格式分类法（显式、可审计）

`scripts/classify_format.py` 以**优先级级联**实现，首个命中者胜出：

| 序 | 标签 | 判定 |
|---|---|---|
| 1 | `empty` | `text.strip() == ""` |
| 2 | `chat_scaffold` | 含 `<think>` / `</think>` / `<|im_start|>` / `<|im_end|>`，或**独占一行**的 `system`/`user`/`assistant`，或 `assistant\n` / `user\n` |
| 3 | `code_fence` | 含 ``` ``` ```，或任一行以 `def `/`class `/`import `/`from X import`/`#include`/`public `/`function `/`fn ` 开头，或 ≥3 行以 `{`/`}`/`;` 结尾 |
| 4 | `json` | 去空白后以 `{`/`[` 开头且 `json.loads` 成功，或匹配 `^\s*[{[]\s*"?\w+"?\s*:` |
| 5 | `refusal` | 前 200 字符匹配 `i'm sorry / i am sorry / i cannot / i can't / as an ai / i'm not able / i don't know / unable to answer`（忽略大小写） |
| 6 | `raw_continuation` | 非空且未命中以上任何一类 |
| 7 | `other` | 解码异常（含 U+FFFD）或无法序列化的文本 |

`raw_continuation` 再按**首行长度**细分（round-156 的头条就是"简洁 vs 脚手架"）：

* `terse`：首个非空行的空白分词 ≤ 6 且无句末标点；
* `long`：其余。

同时报告**领域词法指纹**（对每条生成统计，规则写在分类器里）：
`code_marker_rate`（`def `/`return `/`import `/`print(`/`self.`/`->`/4 空格缩进/`#`）、
`math_marker_rate`（`\` / `$` / `^` / `\frac` / `=` 两侧有数字 / `\theta`）、
`prose_marker_rate`（`the `/` of `/` is `/` was `）。
