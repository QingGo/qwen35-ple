# Round 124：从第一性原理重新审视“Qwen3.8-Flash-Next PLE 嫁接到 Qwen3.5-0.8B”

> 日期：2026-09-08
> 问题：原始愿景是“把 Qwen3.8-Flash-Next 的 PLE 记忆嫁接到 Qwen3.5-0.8B 上，显著提升后者性能”。
> 这个目标可能实现吗？还是不可能？下面从信息论、模型容量、训练预算、已有证据和公开工作出发给出推理链。

---

## 1. 先把“显著提升性能”拆开

“性能”不是一个单变量。至少要区分：

| 任务类型 | 例子 | PLE 是否可能直接帮助 |
|---|---|---|
| 局部低熵续写 | 代码标识符、函数名、重复结构、人名/地名、数字 | 可能 |
| 开放代码生成 | HumanEval 等需要完整程序正确性 | 部分，不稳定 |
| 世界知识 QA | TriviaQA / NQ | 几乎不可能 |
| 数学/推理 | GSM8K / MATH | 几乎不可能 |
| 长上下文利用 | 需要理解文档证据 | 不是 PLE 的强项 |
| 通用对话/指令跟随 | 开放式生成 | 必须 gate，否则有害 |

因此，原问题必须改成：

> 我们想让 0.8B 在**哪一类任务**上“显著提升”？

---

## 2. 第一性原理：外部记忆到底提供了什么信息

### 2.1 PLE / n-gram 记忆的本质

PLE/Engram 记忆本质上是一个**条件 n-gram 查找表**：

```text
context (n-gram)  →  next-token 条件分布 / 外部 value
```

它可以返回：

- 最匹配的 n-gram order；
- 下一个 token 的经验分布；
- 对应的外部文档/value 索引（如果我们构建了 value memory）。

它**不是**一个语义知识库。它只在“当前局部上下文在训练/建表语料中见过”的情况下，提供局部统计信息。

### 2.2 信息论上界

假设：

- 正确答案为 `y`；
- 当前上下文为 `c`；
- 模型隐藏状态为 `h`；
- 记忆返回特征/分布为 `m`。

任何 logit 修正都只是 `(h, m)` 的函数。由数据处理不等式：

```text
I(y ; correction(h, m) | c) ≤ I(y ; h, m | c)
```

如果 `m` 中几乎不包含关于 `y` 的信息，那么任何 scale/bias/gate 都不能从无中创造信息。

对 TriviaQA 这类问题：

```text
正确答案并不由局部 n-gram 统计决定
→ I(y ; m | c) ≈ 0
→ PLE 修正无法带来知识增益
```

这就是为什么我们的 TriviaQA 200 结果仍然是：

```text
exact match = 0.005
```

而不是通过嫁接变成 0.2 或 0.5。

---

## 3. 嫁接成功的必要条件

要让大模型记忆真正帮助小模型，必须同时满足：

1. **记忆里存在有用信息**；
2. **小模型能够读取/理解这些信息**；
3. **小模型有容量把这些信息转化为正确输出**；
4. **训练预算足以训练 reader/projector**；
5. **存在一个可区分的 real/control 信号**，证明不是模型自己“假装记忆”。

### 3.1 条件 1：记忆里存在有用信息

- 对局部 n-gram 任务：是，信息存在。
- 对世界知识任务：通常否。
- 除非 PLE 表存的是“语义 value / 文档证据”，那它已经变成 RAG 的变体，而不是纯 n-gram 先验。

### 3.2 条件 2：小模型能读取

这是最大不确定性，也是最需要“目标侧 reader”的地方。

我们的 PLE Projector 只用了：

```text
hidden_state + 7 个手工 memory features + task one-hot
→ (scale, bias)
```

这是一个非常窄的通道。

XMemTransfer 的工作表明，跨模型 memory transfer 需要：

```text
50M source tokens 建立 source memory
20M target-side fitting tokens 训练 target-side adaptor
```

而我们目前：

```text
10k 训练样本
```

差了大约 3 个数量级。

### 3.3 条件 3：小模型容量

0.8B 模型本身的参数容量是瓶颈：

- 知识、推理、指令跟随主要依赖参数化能力；
- PLE 只能提供“局部先验”或“检索证据”；
- 如果小模型无法在隐藏状态中利用外部证据，外部记忆也救不了它。

我们在联合系统中看到：

```text
RAG 主要提升 knowledge
MoRA 主要提升 arithmetic / code-output
PLE 单独在通用任务上几乎无收益
```

这与“外部记忆不能替代参数化能力”一致。

### 3.4 条件 4：训练预算

公开的 target-side reader 方法：

| 方法 | 训练预算 |
|---|---|
| XMemTransfer | source 50M / target 20M |
| Memory Grafting | 大规模预训练场景 |
| 我们当前 | 10k 样本 / 80–100 步 |

如果目标是“显著提升”，10k 样本几乎肯定不够。

### 3.5 条件 5：real/control

我们已经在内部验证过：

- 真实记忆 vs 控制记忆在 code/name 上可区分；
- 但在知识任务上几乎无差异；
- hidden-state 直接注入即使 loss 下降，也可能无法通过 real/control。

这说明：**仅仅“看起来有记忆”不等于“真正使用了记忆”**。

---

## 4. 从我们的实验数据看边界

### 4.1 哪些已经证明可行

- 10k 局部续写，5 seeds：
  ```text
  projector vs fixed NLL = +0.2249
  CI = [0.1436, 0.3255]
  5/5 seeds 为正
  ```
- HumanEval pass@k 10×3：
  ```text
  base 0.40 → BM25+PLE 0.70
  ```
- HumanEval greedy 50：
  ```text
  base 0.22，BM25+PLE 0.10
  BM25+PLE 仍恢复 4 道 base 未通过题
  ```

这说明：**PLE 在局部、低熵、代码/名字类任务上确实有真实信号，但不是均匀的正向提升。**

### 4.2 哪些已经证明不太可能

- TriviaQA 200：`exact match = 0.005`
- LLM judge：HumanEval BM25+PLE 分数低于 base
- 开放生成：无 token policy 时会退化
- 综合任务：PLE 单独无法与 RAG / adapter 竞争

---

## 5. 第一性原理下的结论

### 5.1 可实现的部分

```text
目标：让 0.8B 在“局部低熵代码/命名/数字续写”任务上显著提升
```

这是**有可能**的，前提是：

- 使用足够规模的 target-side reader / projector；
- 训练数据至少从 100k 到 1M–20M token；
- 使用 real/control 证明；
- 使用 token policy 防止开放生成退化；
- 把 PLE 定位为“可审计局部记忆”，不是通用知识库。

### 5.2 几乎不可能的部分

```text
目标：让 0.8B 在“世界知识、数学、推理、通用对话”上显著提升
```

这是**几乎不可能**，原因是：

1. PLE 局部 n-gram 表中没有这些知识；
2. 如果表中有语义 value，那它已经变成 RAG，需要检索/阅读器，不是纯 PLE；
3. 0.8B 参数容量不足，不能仅靠外部先验补足；
4. 我们当前训练预算和公开方法相差 3 个数量级；
5. 已有实验数据一致显示边界。

---

## 6. 更可能实现原始愿景的替代路径

原始愿景真正想要的是：

> 用大模型/大记忆让 0.8B 变强。

这条路径更可能通过以下方式实现：

| 路径 | 原理 | 可行性 |
|---|---|---|
| **蒸馏** | 用 Qwen3.8-Flash-Next 生成教师数据，训练 0.8B | 高，比 PLE 直接嫁接更直接 |
| **RAG / 文档记忆** | 外部文档作为证据，0.8B 做阅读/抽取 | 中高 |
| **参数化 adapter（MoRA/LoRA）** | 注入任务能力 | 中高 |
| **PLE + 上述混合** | 作为局部低熵通道 | 中，但只作为补充 |
| **纯 PLE 全能力嫁接** | 期望 n-gram 表直接替代参数能力 | 低，基本不可行 |

---

## 7. 如果要继续验证“能否实现”，最小实验序列

1. 建立更大的 target-side reader（不是简单 MLP，参考 XMemTransfer 结构）；
2. 用 1M / 5M / 20M token 分别训练；
3. 在真实知识 QA + 代码 + 局部续写三组任务上评估；
4. 始终跑 real / control / shuffled；
5. 如果 20M 后：
   - 局部任务显著提升 → 窄目标可行；
   - 知识任务仍接近零 → 宽目标不可行；
6. 若宽目标不可行，就明确记录为“负结果 + 边界”，转向蒸馏/RAG。

---

## 8. 最终回答

> 从第一性原理看，**“把 Qwen3.8-Flash-Next PLE 嫁接到 Qwen3.5-0.8B 并显著提升通用性能”这个原始愿景，在当前框架下基本不可能实现。**

但：

> **“让 0.8B 在局部低熵、可审计的 n-gram 记忆任务上显著提升”是可能实现的**，只是需要远大于当前 10k 样本的训练预算和更强大的 target-side reader。

我们最诚实的定位应该是：

```text
PLE / n-gram 外部记忆 = 可审计的局部低熵记忆通道
RAG = 文档级证据通道
Adapter = 参数化能力通道
Distillation = 把大模型能力真正压入小模型
```

它们互补，而不是互相替代。
