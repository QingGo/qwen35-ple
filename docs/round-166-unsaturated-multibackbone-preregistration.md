# Round 166 预注册：非饱和 regime 能不能在别的骨干上复现？

状态：**规则已冻结，实验尚未运行。**

## 1. 为什么问这个

round 162 §3.7 是全文唯一的**正面**结果：撤掉答案长度天花板（`NO_SFT=1`）之后，
粗分类法看不见的四个细格式描述子**全部越出** split-half 地板，
两条强方向性预测（code 臂的代码标记 > wiki；wiki 臂的散文标记 > code）**都通过**，
于是副判决给出 `CONTENT_DEPENDENT` —— 也就是说**界允许的那部分先验确实到达了输出**。

审稿人第 3 条指出：那个正面结果只有 **600 条 / 一个骨干 / 一个配方**。
如果它只是 0.8B 的偶然，论文的"分层"论证就塌了一半。这一轮做复现。

## 2. 做法：不引入任何新的判定自由度

**完全复用 round 162 的队列、条目集、臂定义、超参与分析脚本**，只换骨干：

- 队列：`scripts/run_round162_format_prior.sh`，`NO_SFT=1`，六臂齐全
  （1 wiki / 2 code / 3 stem / 4 wiki-shuf / 5 ple-off / 6 no-reader）
- 条目：`data/qa-standard/eval-600b.jsonl`（600 条，200/200/200）
- 步数、学习率、seq-len、reader 架构（`--reader official --bridge-mlp --out-mlp`）与主实验一致
- 分析：`scripts/analyze_round162.py`，**脚本与判定规则逐字不变**

**批大小按骨干钉死，与该骨干已有的饱和实验一致**，这样每个骨干内部
「饱和 vs 非饱和」只差 `NO_SFT` 一个开关：

| 骨干 | dtype | `BATCH_SIZE`/`BATCH_TOKENS` | 依据 |
|---|---|---|---|
| 4B | bfloat16 | **4 / 2048** | 与 `round162-4B` 饱和实验逐字一致 |
| 2B | bfloat16 | **8 / 4096** | 队列默认，与 0.8B 各轮一致 |

> **一次在结果之前做出的协议更正（记录在案）**：4B 首轮误用队列默认 8/4096 启动，
> 第一个臂峰值显存 22,552 MiB（上限 24,564 MiB），既偏离 4B 已有配方又有 OOM 风险。
> 在**任何判决数字产生之前**已停止并改用 4/2048 重跑，已完成的 `arm-wiki.json`
> 作废删除（它是 8/4096 训练的，与其他臂不同配方，混用无效）。
> 判定规则、臂定义、条目集与阈值均未改动。

**这一轮不新增阈值、不新增描述子、不改臂定义。** 新骨干上的判决要么与
0.8B 相同、要么不同，二者都直接可读。

骨干：**4B**（bfloat16）与 **2B**（bfloat16，queue 需扩一个分支）。
2B 的 dtype 与 0.8B（float32）不同，这一点在结果里如实标注。

## 3. 先决条件：天花板必须真的被撤掉

非饱和 regime 的整个意义在于生成长度不再被压到 2 token。若某骨干上
**生成 token 均值 ≤ 3**，则该骨干仍处于饱和，regime 不成立，一律判
`SATURATION_NOT_LIFTED`，不得用它的判决支持或反驳任何东西。
（0.8B 参考值：wiki 14.65 / code 11.14 / stem 17.23 / no-reader 20.59。）

## 4. 判定规则（先冻结，逐骨干独立判定）

按下列顺序，第一个命中的即为结论：

| 标签 | 条件 |
|---|---|
| `SATURATION_NOT_LIFTED` | 任一注入臂生成 token 均值 $<= 3$ |
| `REPLICATES` | 生成 token 均值 $> 5$，**且** code$>$wiki 与 wiki-散文$>$code 两条方向性预测的**单侧 $p < 0.05$ 且方向一致**，**且**四个细描述子中**至少 3 个**越出各自的 split-half 地板 |
| `PARTIAL` | 上述三项中有两项成立 |
| `FAILS_TO_REPLICATE` | 其余 |

两条方向性预测的定义、符号与单侧检验方向与 round 162 §0 完全一致：
`code` 臂的代码标记率减去 `wiki` 臂的（预测为正），
`wiki` 臂的散文标记率减去 `code` 臂的（预测为正）。

第三条方向性预测（`stem` 的数学标记 $>$ `wiki`）在 0.8B 上是 **null（$p=0.16$）**，
本轮**照报**，且**不参与**判定 —— 因为语料本身没有把这一对分开，
它在 0.8B 上的 null 是预期内的，不应该被当成复现失败，也不应该被用来充数。

## 5. 可能的结局与各自的含义

- **两个骨干都 `REPLICATES`**：正面结果不是 0.8B 的偶然，§3.7 的分层结论可以
  从"一个骨干上的观察"升格为"跨骨干成立"，Limitations 第 2 条相应收紧。
- **一个复现一个不复现**：必须报告是哪个骨干、差在哪一项，并把它写成
  骨干依赖的边界，而不是悄悄只报成功的那个。
- **都 `FAILS_TO_REPLICATE`**：0.8B 的正面结果降级为单骨干观察，
  这是对论文不利的结果，照原样写进正文与 Limitations。

**不允许**在看到结果后更换骨干、换条目集、换步数或改判定阈值。
