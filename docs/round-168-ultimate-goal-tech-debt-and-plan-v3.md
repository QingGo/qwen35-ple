## 0. TL;DR

1. **目标需要第四次修正，这次加的是"天花板 vs 可实现"的两层区分。**
   我们**所有**测量都在"可实现"层（受解码器限制），而"天花板"层
   （`I(future; trigram | h_t)`，与解码器无关）**从未被真正测量过**。
   **再加一百个解码器变体也定不了案 —— 因为它们在同一个受限层里。**
2. **本轮最大的概念债是"把解码器受限的测量当成通道属性"**（TD-9）。
   造 CMI 探针时当场证伪了这条：**线性解码器对互补信息完全失明**
   （合成对照 excess −0.44 vs MLP +2.2）。我们所有"零"都建立在近-oracle 探针的隐含假设上。
3. **本轮最大的概念发现是"率分配错配"**（TD-11）：
   表的容量按**哈希频率**分配，不按**重要性**分配。
   推论：**冻结表的实验测的是一条可证明不正确的分配规则** ——
   四十个零是那个设计选择的**必然结果**，不是意外。
4. **计划 v3 = 加 Stage 1.5（天花板测量，最高优先）+ 降级 Stage 2/3 + 明确停止清单。**
   冻结嫁接的能力线**关闭**；剩下的是工程主张（确定性卸载）与边界条件论文。

## 1. 终极目标（第四版）

### 1.1 四次修正的轨迹

```text
v0 原始        纯 PLE 嫁接，通过少量训练显著提升 0.8B 通用性能
v1 round-153   在固定"激活算力+内存"下，外部记忆何时胜过同预算纯参数？   ← 从"能否"到"何时"
v2 round-157   ＋ 该通道不可能承载上下文条件化知识（可证明）
v3 round-167   ＋ 价值若存在，在"释放有效深度/表面先验"轴上
v4 本文        ＋ 【天花板 vs 可实现】的两层区分 —— 且必须先测天花板
```

### 1.2 为什么 v4 是必要修正

**表面上**，本轮得到了两个方向相反的结果：

| 论证 | 结论 | 出处 |
|---|---|---|
| **压缩论证** | 有损泛化压缩器只保留率预算内降低损失的东西 ⇒ 记忆的生态位是"高价值 ∧ 高精度 ∧ 罕见" ⇒ **结构上很薄** | 本 session 综合 |
| **密码学类比** | 信息可以完整存在但**对给定解码器不可及** ⇒ 测到的零**不能**推出信息不存在 | 本 session 更正 |

**它们不冲突，因为它们作用在不同对象上：**

| | 映射 | 对信息做什么 | 管辖什么 |
|---|---|---|---|
| **有损压缩**（骨干） | 多对一（满射） | **销毁**，不可逆 | 骨干**缺**多少 |
| **加密**（表的编码） | 一一（双射） | **保留**，只换编码 | 我们**能读**多少 |

合成：

$$\text{记忆的有用性} \le \min\big(\underbrace{\text{表保留了多少}}_{\text{密码学管辖}},\; \underbrace{\text{骨干丢了多少}}_{\text{压缩论证}},\; \text{且对损失有用}\big)$$

**由此得到方法论的硬结论：**

> **任何"记忆无用"的断言，必须是关于天花板的断言，不能是关于被测值的断言。**

而我们**所有**历史测量都在"可实现"层（探针、PR、cos、CMI），**全部受解码器限制**。
**这就是为什么"再试一个 reader"定不了案** —— 它在同一个受限层里绕圈。

### 1.3 v4 目标陈述

> **测定外部记忆通道的信息论天花板（与解码器无关），并判定它是否在任何可识别的生态位里足够高。**

| 子目标 | 判定问题 | 解码器依赖 | 状态 |
|---|---|---|---|
| **(a) 天花板** | `I(future; trigram \| h_t)` 有多大？ | **无关** | **从未真正测量** —— `round-158` 的 4.94 只是 1M token 计数模型，是**偏悲观**的代理 |
| **(b) 可实现** | 可行解码器族能兑现天花板的百分之几？ | 依赖 | 已大量测量（线性 ~59%、PR、CMI） |
| **(c) 生态位** | 在"骨干无能 ∧ 表有能"处天花板是否显著更高？ | **无关**（两侧都可测） | 已设计（margin 筛选），未执行 |
| **(d) 工程价值** | 确定性寻址的卸载收益 | 无关 | 已有端侧读数（NVMe 462K rows/s） |

**停止规则（v4）**：若 (a) 在所有可识别生态位上都低，则**能力线诚实关闭**，
交付物 = **边界条件论文 + 工程形态**。若 (a) 在某生态位显著高，则 (b) 与 Stage 3 才有意义。

## 3. 本 session 暴露的新技术债

### TD-9 解码器受限的测量被当成通道属性（P0，概念债 —— 本轮最贵）

* **实例**：线性探针在互补信息上完全失明（合成对照 excess −0.44 vs MLP +2.2）；
  `round-161` 的"回收 ~59%"被当作**通道**的容量，而它只是**那个解码器**的容量。
* **根因**：没有为"信息量"类结论声明解码器族，也没有容量曲线。
* **修复**：(i) 结论必须声明解码器族；(ii) 必须附**容量曲线**；(iii) 报告 **null 超额**而非原始差。

### TD-10 天花板从未被测量（P0）

* `round-158` 的 **4.94** 来自 **1M token** 计数模型，对真天花板是**宽松（偏悲观）**的代理。
* 而这**恰好是唯一 decoder-independent 的量** —— 也是唯一能定案的量。
* **修复**：在远大于 1M 的语料上建计数模型；或直接估 `I(future; trigram | h_t)`。

### TD-11 率分配错配从未被写下（P0，概念债）

* 表的键是 token 序列的**哈希** ⇒ **容量按哈希频率分配，不按重要性**。
  每个 trigram 按出现频率分到一条 2560 维行，而不是按"知道它有没有用"。
* **推论**：**冻结表的实验测的是一条可证明不正确的分配规则。**
  这就是为什么**共训不是细节，而是让行按重要性成形的唯一途径**。
* **修复**：写进任何冻结表实验的**筛选条件**；并作为"必须共训"的理论依据。

### TD-12 规模衰减被归档为失败，其实是预测被证实（P1）

* `round-166`：散文效应 0.8B **+0.4159** → 2B **+0.5832** → 4B **+0.0098（p=0.44）**。
* 压缩论证**预测**"n-gram 记忆的能力增益随规模缩小"（更大模型的注意力更会查找、MLP 装得更多）。
* **修复**：重新归档 —— 它现在是 v4 的**支持证据**，不是失败。

### TD-13 "关键超参不可达"是复现模式（P1）

* `zero_init_out` 曾是字面量（Stage 0.3 已修）；
* **`weight_decay` 至今是 `AdamW` 默认 `0.01`，无开关**（`run_phase0.py:361`）。
* 检索到 [arXiv 2410.23819](https://ar5iv.labs.arxiv.org/html/2410.23819)（weight decay 诱发低秩）——
  这是一个**便宜、可否证、从未试过**的假设。
* **修复**：扫一遍其它硬编码默认值；把"超参可扰动"作为实验准入条件。

### TD-14 新仪器必须做**双向**验证（P1，方法论）

* 本轮 CMI 探针在**制造过程中连错两次**（线性失明、宽度偏置）。
* **修复**：新仪器入册前必须有 (i) **阳性对照**证明功率 (ii) **null 对照**证明假阳性率。
  写进 `docs/gpu-utilisation-playbook.md` 同级的协议文档。

### TD-15 运维自伤三例（P2，已进 playbook）

裸 `wait` + 无限后台采样器 = 死锁；`pkill -f <pattern>` 杀掉自己的 SSH 会话；
heredoc 嵌套引号导致脚本静默未生效。**教训：运行产物存在性判据，不要判控制流。**

## 4. 开发计划 v3

### 排序原则（本轮新增）

> **先测天花板，再谈实现。** 在受限层里加解码器变体是**零信息**的。

```text
Stage 0   还债                                    ✅ 完成
Stage 1   机制轴 + 读出配置                        ✅ 完成（1a 无 DEPTH_FREED；1b 架构性）
Stage 2   设计空间扰动（gate 选择性）              ⏳ 运行中 → 出判定后**收尾**
Stage 1.5 【新，最高优先】天花板测量               ← 本轮新增
Stage 3   共训小表                                ⛔ 仅在 1.5 显示有空间时启动
Stage 4   iso-budget 判决 + 端侧形态               ← 工程线的交付物
```

### Stage 1.5 —— 天花板测量（decoder-independent）

| # | 事项 | 为什么决定性 | 成本 |
|---|---|---|---|
| **1.5a** | **把天花板推紧**：在 ≫1M token 上建计数模型，给出 `P(next\|trigram)` 的**渐近**交叉熵 | 4.94 是偏悲观的代理；这是唯一与解码器无关的量 | CPU 天级 |
| **1.5b** | **直接估 `I(future; trigram \| h_t)`**：用 CMI 探针，但把"行"换成 **trigram 身份特征**（不经过读出） | 绕开读出，直接问"trigram 里还剩多少 `h_t` 没有的" | CPU 天级 |
| **1.5c** | **margin 分布**：`margin(t) = L_bb(t) − L_cnt(t)`，找"记忆占优"的正尾 | 无正尾 ⇒ 生态位为空，**整条线免费关闭** | 无 GPU |
| **1.5d** | **WD 消融**（TD-13）：`weight_decay=0` 两次训练 | 最便宜，且完全未测 | GPU 分钟级 |

**出口判据**：

```text
IF 1.5a/1.5b 的天花板在所有生态位都低（相对骨干自身 NLL）
    => 能力线关闭。交付：边界条件论文 + 端侧工程形态（Stage 4）
ELSE IF 某生态位天花板显著高
    => 该生态位就是靶子 → 启动 Stage 3（共训）+ 按 margin 选样
```

### Stage 2 的收尾（不是扩展）

gate 选择性（2.2）跑完后**出判定即止**。
**Stage 2.1（双层注入）建议砍掉** —— 压缩论证说它只是**再加一条同样按错误分配冻结的通路**。

## 5. 借鉴矩阵（新增项）

原则不变：**只借机制，不复制实现；每层唯一真源；跨仓 golden 对拍；只新增不改语义。**

### 5.1 本轮新增（外部）

| 我们缺的机制 | 从谁借鉴 | 具体接缝 | 明确不做 |
|---|---|---|---|
| **区分"解码器无关/受限"的论断** | 密码学（陷门单向函数） | 每个"信息量"结论标注：天花板（无关）vs 可实现（受限）；并用**密钥空间**（族/容量/时间/初始化/目标/输入集）组织实验 | 不把"测不到"写成"不存在" |
| **训练时间是钥匙的一个维度** | [arXiv 2512.20607](https://ar5iv.labs.arxiv.org/html/2512.20607) | saddle-to-saddle：平台期 + 每次秩 +1。我们**只训过 500 步** | 不把预算不足写成架构结论 |
| **正则化→低秩机制** | [arXiv 2410.23819](https://ar5iv.labs.arxiv.org/html/2410.23819) | `weight_decay=0` 消融（1.5d） | 不把它当解释，只当可证伪假设 |
| **长尾不是记忆的朋友** | [Nishida 2025, NAACL Findings](https://aclanthology.org/2025.findings-naacl.331.pdf) | 选样时区分"语料罕见"与"表里罕见"（两条不同的轴） | 不朴素追长尾 |
| **只在必要时用记忆** | [Mallen 2023, ACL](https://arxiv.org/abs/2212.10511) | `margin` 选样规则；必要性可测（去掉记忆的性能损失） | 不在记忆冗余处评估 |
| **率分配是设计轴** | MoE / PKM / UltraMem | 借**按学出来的重要性分配**这一原则，用来**论证 n-gram 哈希分配为何是错的** | 不引入 product-key 作主路径 |

### 5.2 兄弟仓库（不变）

| 仓库 | 借什么 | 边界 |
|---|---|---|
| **EngramDB** | 表写入/打包、行级 patch、Store-P 预取、bundle | **不自创行格式、不写第二个存储引擎** |
| **engram-peft** | hash / gate / ShortConv 权威语义 + golden | **不写第二套实现**；只新增字段 |
| **LLM-CompileForge** | 推理编译器（**我们不依赖也不被依赖**） | 依赖方向 `CompileForge → EngramDB` |

### 5.3 冲突规避（新增第六条）

1. 每层唯一真源，跨层用 adapter；2. 跨仓 golden 对拍 + 版本 pin；
3. 共享评测协议；4. 一个统一 trainer；5. 存储永远 EngramDB，serving 永远 bundle；
6. **【新】评测协议** —— 任何"信息量"类结论必须携带
   **(解码器族, 容量曲线, null 超额, 天花板对照)** 四元组，否则不许进结论表。
   （对应 TD-9 / TD-14）

## 6. 与目标的距离（诚实评估）

### 已经拿到

* **一条可证明的界**（`round-157` §1.1，源码逐行核实）：token n-gram 哈希寻址
  **不可能**承载上下文条件化知识。这是本项目最硬的产出，且**与 reader 无关**。
* **一套可复用的尺子**：计数参照系、长尾分解、塌缩溯源、长度混淆审计、
  **CMI 探针（含双向验证）**、GPU 利用率手册。
* **两个强机制结论**：塌缩是**目标的解**（1b）；注入效应**内容无关**（1a）。
* **一个概念框架**：压缩 ↔ 密码学**两层区分**，它解释了为什么过去的路线定不了案。

### 还没拿到

* **天花板**（唯一 decoder-independent 的量）—— **一次都没测过**。
* 生态位是否存在（margin 分布）。
* 表在可训练时能否被使用（codebook，Stage 3 的旗舰）。

### 诚实的一句话

> **我们花了四十轮优化"能不能读出来"，而从来没测过"那里到底有多少"。**
> v4 把这个顺序倒过来 —— **先测天花板，再谈读出。**

❌ 停止：在受限层里加解码器变体 —— 那是零信息
❌ 停止：Stage 2.1 双层注入 —— 只是再加一条按错误分配冻结的通路
❌ 停止：把"测不到"写成"不存在" —— 密码学类比已证这是无效推理

✅ 开始：1.5a/1.5b 天花板测量（decoder-independent）
✅ 开始：1.5c margin 分布（无 GPU，能否决整条线）

另一半是知道收手之后去测哪个数。
