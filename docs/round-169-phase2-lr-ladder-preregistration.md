## 0. 一句话

B1 的 `ROWS_HARMED` 是在 **lr=1e-3 发散**的优化器上测出来的;在收敛的 lr=1e-4 下,
训练行的代价只剩 1.5%,而且**按频率分层后符号翻转**。
本阶梯问的是唯一还没被问的问题:**存不存在一个让总体 Δ 为正的 lr。**

## 1. 符号约定(全项目统一,禁止改写)

```
delta = frozen - trained        (nats)
```

**Δ > 0 表示训练行比冻结行更好。** 记录处是 `round169_eval_rows.py` 的 `delta = lf - lt`。
本次核对的三个已知点:

| 点 | Δ | mean_nll frozen | mean_nll trained | 读数 |
|---|---|---|---|---|
| lr=1e-3, 4ep | **−0.33127** | 2.56906 | 2.90033 | 训练差 0.331 |
| lr=1e-4, 4ep | **−0.00272** | 2.56906 | 2.57178 | 训练差 0.0027 |
| **注入本身**(frozen − none) | **−0.17593** | 2.56906 | 2.74499(纯骨干) | 注入买到 0.176 |

第三条是尺度:0.176 是"有记忆"相对"无记忆"的价值,0.0027 是训练它要付的代价。

---

## 2. 为什么这一级值得插队

原队列的顺序是 `wiki-e1 → code B1 → stem B1`,即在另外两个域上**复现 lr=1e-3**。
新证据把这件事的优先级改了:

1. **lr=1e-3 的逐 epoch 训练损失是 3.0555 → 3.1646 → 4.1414 → 3.4710**,即它在训练流上
   **发散**;lr=1e-4 是 2.9739 → 2.9556 → 2.9371 → 2.9178,**单调下降**。
   所以 −0.33127 是**发散优化器的损伤**,不是行的一条性质。
2. **复现一个已经发散的配置,信息量低于测量决定"该不该训行"的那条曲线。**
3. code/stem 是**推迟**,不是取消:预注册仍然只管 wiki,阶梯的任何结果都**不能**修改 B1 的冻结判决。

## 3. 规则(已冻结,逐字来自启动的脚本)

```
点 1: lr = 3.1622776601683795e-4 = sqrt(1e-4 * 1e-3)   # 几何中点
      参考: REF_DELTA = -0.0027166083372815774        # lr=1e-4 的实测值

if delta(3.162e-4) > REF_DELTA:      # 严格更好
    点 2: lr = 5.623413251903491e-4 = sqrt(3.162e-4 * 1e-3)
else:
    停。判据:曲线在该区间单调,最优 lr 在 1e-4 或更低,爬升只会加发散损伤。
```

**不变量**:所有点共用同一个 `E0`(硬链接保护)、同一个 reader
(`round162-0.8B-nosft/reader-wiki-seed0.pt`)、同一条 eval 流、`epochs=4`、`arm=real`、
`seed=0`。**唯一变量是 lr。**

**为什么点数上限是 2**:每点 ≈ 80 min 训练 + 11 min eval。两点是 3 小时。
在"总共只跑一夜"的约束下,这已经把预算用满。

## 4. 两个互斥假设(这是解读,不是预测)

| | 内容 | 若成立,看到什么 |
|---|---|---|
| **H_单调** | Δ 关于 lr 单调下降,最优在 lr→0(此时 Δ→0) | 点 1 的 Δ 比 −0.00272 更负 ⇒ 停梯;**不存在正点,冻结就是最优策略** |
| **H_峰** | Δ 有内部极大:高频带的收益先到峰,低频带与"继承行"的损伤后到 | 点 1 的 Δ 优于 −0.00272 ⇒ 继续爬,点 2 从另一侧夹住峰 |

**H_单调 若成立,是一个干净且可发表的否定结论**:在这条链上(冻结骨干 + 冻结读出),
PLE 行**不应该被训练**,不是"训不好",而是"训练的最好结果是零"。

**H_峰 若成立**,是本项目第一次出现"训练记忆层有净收益"的读数。

| 频带(train 计数) | n | Δ(lr=1e-3) | t | Δ(lr=1e-4) | t |
|---|---|---|---|---|---|
| [1,1] | 50,670 | −0.52220 | −51.46 | −0.00899 | −6.17 |
| [2,2] | 25,020 | −0.42189 | −31.67 | −0.01107 | −4.70 |

| [10,49] | 58,102 | −0.25946 | −38.44 | **+0.00164** | +1.15 |
| [50,199] | 37,070 | −0.18797 | −25.88 | **+0.01596** | +8.26 |
| [200,+] | 62,071 | −0.18039 | −36.55 | **+0.02147** | +13.26 |

按"自身三元组在训练流里出现过没有"二分,差别更大:

| 位置类别 | n | Δ(lr=1e-3) | Δ(lr=1e-4) |
|---|---|---|---|
| 上下文出现过(计数 ≥ 1) | 293,143 | −0.30963 | **+0.00267** |
| **上下文计数为 0** | **150,317** | −0.37346 | **−0.01322** |
| 全体 | 443,460 | −0.33127 | −0.00272 |

**读数**:在 lr=1e-4 下,**上下文见过的 293k 个位置总体是赚的(+0.00267)**,
把总体拖负的是那 **150k 个"上下文计数为 0"的位置(−0.01322)**。

> ### ⚠️ 上面这张表的分带变量错位一格 —— 见
> [`round-169-band-variable-off-by-one.md`](round-169-band-variable-off-by-one.md)
>
> 本文件 §5 最初把"计数为 0"读成"这个位置**继承了**别人投票的行"。**实测否定了这个读法**:
> `context_counts[t]` 数的是**结束于 `t-1`** 的三元组,而位置 `t` 注入的是**结束于 `t`** 的那一行
> (297,998/297,998 = 100.0% 吻合,零反例)。`trigram_codes` 又是**单射不是哈希**,
> 所以"继承一行"在机制上根本不存在。
>
> ⇒ **本表的 Δ 数值仍然有效(Δ 不分带),但"哪个频带"这个标签是错的。**
> 正确的分带要用 `own = trigram-train-count[snapshot_index]`,由
> `scripts/round169_reband.py` 从阶梯自带的逐位置记录算出。**阶梯的动机不受影响**
> (动机是"总体的负号来自低频那一侧",而这一点在新旧变量下都是待测的,不是已知的)。

## 6. 本轮为阶梯做的手术(全部可审计)

1. **`E0.npy` 改硬链接保护**。阶段 1 的队列在第一步 eval 之后会 `rm -f E0.npy` 来回收
   6.83 GB。阶梯的每个点都要用同一个 `E0`,而 11 GB 剩余空间**放不下一份拷贝**。
   `ln` 到 `/root/autodl-tmp/qwen35-ple/E0-wiki-keep.npy`(同 inode、同设备、**零额外占用**),
   队列的 `rm -f` 只把 nlink 从 2 降到 1,数据活着。确认过:`12893333799 nlink=2`。
2. **停掉阶段 1 队列**,并清掉它可能已经起的 code 局部快照。它没跑到的 code/stem 未受影响。
3. **`round169_eval_rows.py` 增加逐位置记录**(`<out>.deltas.npz`):
   `score / rowid / snapshot_index / trigram_code / delta / nll_frozen / nll_trained / nll_none / context_count`。
   `rowid`(分片表的行)与 `snapshot_index`(训练真正移动的那一行)**是两个不同的键**,
   只留一个就分不清"自己的三元组被训过"和"继承了别人投票的行"。
   该写入在**主结果 flush 之后**、且被 try 包住,所以它**不可能**弄丢花了 GPU 时间的部分。
   这是**追加**:主 JSON 的数值不受影响,但必须记录在案 —— lr=1e-4 的 eval 用的是加这一项**之前**的代码。
4. **收集器换成按大小抓取**(`--max-size=20m`),而不是手写 include 列表。
   手写列表这次已经漏掉过一次文件;大小规则不会过期。

## 7. 承限

1. **只有 4 个 lr 点**(含已知的两个),是一条粗曲线,不是"最优 lr"的估计。
2. **只训 1.5% 的表**(121,488 / 667,404 快照行,快照本身也只是整表的子集)。
3. **读出与骨干都是冻结的**。即使出现正点,也只能推出"在这个冻结读出下可以训",
   推不出"共训一定更好"。
4. **点 2 是否执行由点 1 的结果决定**,所以两个点不是独立证据,不能当两次复现来数。
5. 阶梯的**规则**先验,但**本文件的假设命名**后验(§ 状态)。
