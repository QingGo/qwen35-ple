## 2. 一个统一解释：塌缩是**目标函数的最优解**，不是架构缺陷

### 2.1 理论依据：saddle-to-saddle 与 simplicity bias

[arXiv 2512.20607](https://ar5iv.labs.arxiv.org/html/2512.20607)（ICLR 2026）给出了一个跨架构的统一框架：

> 梯度下降**逐步学习复杂度递增的解**。**"简单"的操作定义就是有效单元数** ——
> **线性网络是更低的秩**。学习过程是 saddle-to-saddle：停留在一个鞍点，
> 沿不变流形演化，再跳到下一个鞍点，每次**把有效宽度 +1**。

关键推论：**网络只在损失*要求*时才提升秩。**
> "the emergence of stage-like dynamics can hinge on the data distribution and
> architectural choices"；"the same architectures can also exhibit smooth,
> exponential training dynamics, simply by changing the initialization"

### 2.2 套到我们身上，一次解释 S1/S2/S3

我们的读出停在 `PR(c_t) = 1.020`（秩 1）。按 saddle-to-saddle，
**这说明秩 1 就已经把训练损失做完了** —— 没有理由爬到秩 2。

于是：

| 观测 | 解释 |
|---|---|
| **S1** 初始化无影响 | 固定点层级是**损失地形**的性质；初始化只改变**停留多久**，不改变**终点**。已收敛则终点相同。 |
| **S3** 深度只差 10% | 同样：秩 1 的损失值在两个深度下都可达，深度只影响路径。 |
| **S2** 冻结投影吃掉 6.53× | 冻结投影**不在优化范围内**，它的秩是给定的；它把 136.7 压到 20.9，而剩下的部分只需再压到 1 就够了。 |
| PR 精确等于 1.020（历史 reader 与重训 reader 的中间几何完全不同：`value_proj` 14.4 vs 20.9、`branch_sum` 2.68 vs 4.46，**最终都恰好 1.020**） | 最终秩由**目标的解**决定，不由路径决定 —— 一个强吸引子签名。 |

**一句话：读出没有坏，它正确地学到了"内容没用，只需要一个常数推挤"。**
这也和 Stage 1a 完全一致：4B 的深度几何位移**对内容不敏感**
（`real == shuf`），因为一个与内容无关的常数推挤就足够满足目标。

### 2.3 一个新发现的候选机制：weight decay

`scripts/run_phase0.py` 第 361 行：

```python
optimizer = torch.optim.AdamW(params, lr=lr)
```

**`AdamW` 的 `weight_decay` 默认是 `0.01`，而我们的 CLI 里没有任何开关可以改它。**
（与 Stage 0.3 修的 `zero_init_out` 是同一类债：**关键超参不可达**。）

检索到 [arXiv 2410.23819 "Weight decay induces low-rank attention layers"](https://ar5iv.labs.arxiv.org/html/2410.23819)：
正则化与低秩之间存在直接机制。我们**从未察觉**训练一直在施加权重衰减。

**这是一个便宜、可否证、且完全没试过的假设**：把 `weight_decay` 设为 0，
若 `PR(c_t)` 显著上升，则塌缩有一部分是正则化造成的，而不是目标或架构。

> 诚实标注：该论文讲的是 attention 层，对**线性读出**的适用性是**待验证**的推测，
> 不能当作结论。但它把"从未察觉的默认值"变成了一个可做的实验。

## 3. 新方向（按"有望提升效果 × 创新 × 适用范围"排序）

### D1（最高）让记忆**变得必要**：反事实必要性训练

**逻辑**：如果秩 1 就够，那是因为**骨干自己已经能预测**，记忆是冗余的。
那就不该修读出——**该改任务，让记忆成为唯一的信息来源。**

三种构造，从最可控到最真实：

| 构造 | 做法 | 为什么决定性 |
|---|---|---|
| **D1a 局部窗口消融** | 训练时把骨干对**最近 k 个 token 的注意力/状态**屏蔽，只留记忆能提供该信息 | **反事实**：成功率在没有记忆时**恰好为 0**。若此时读出仍停在秩 1，则塌缩是真正的架构/优化壁垒；若秩上升，则塌缩**是目标造成的**，可修 |
| **D1b 未见语料** | 在骨干**预训练分布之外**的语料上训练/评测（私有、合成、长尾） | 我们至今**全部**语料都是骨干见过的；记忆本应只在权重压不住的地方付钱 |
| **D1c 长尾语言建模** | `round-157` §7.2 早就点名、从未做过的目标 | 与官方三家的"长尾 LM 目标"对齐 |

**为什么创新且适用范围广**：它把问题从"如何修读出"变成
**"如何让外部记忆成为信息论上必要的"** —— 这是一个**架构无关**的原则，
对 Engram/PLE、kNN-LM、RETRO、任何外部记忆都成立。而且它给出一把通用尺子：
*记忆的必要性 = 去掉记忆后的性能损失*。

### D2 rank-promoting 目标：把"秩"从症状变成可优化量

既然 saddle-to-saddle 说**秩由损失要求决定**，那就**显式地要求它**：

* **对比目标**：同一上下文、不同行 → `c_t` 必须不同（直接对 `cos(real, shuf)` 施压）；
* **核范数 / 正交正则**：直接奖励 `c_t` 的有效秩；
* **信息瓶颈**：在保留任务信息的前提下最小化 `I(c_t ; e_t)` 的冗余。

**创新点**：把 `round-165A` 的 `PR` 阶梯从**诊断指标**升级为**训练目标**。
**适用范围**：任何"读出塌缩"的模块（记忆层、adapter、adapter-style 投影）。

### D3（最便宜，立即可做）关掉 weight decay

一个 flag + 两次训练。若 PR 上升 → 塌缩的一部分是正则化。
**必须与 D1 一起解释**：若关掉 WD 秩上升但**任务指标不变**，说明秩不是瓶颈（与 Stage 1b 一致）。

### D4 查询相关寻址：唯一能绕开可证明界的路

`round-157` §1.1 的界是**可证明**的：16 个头只依赖 (t−2, t−1, t)。
所以"上下文条件化的知识"在这条通道上**永远**做不到。
唯一绕开的办法是**查询相关寻址**（kNN-LM / RETRO 式真检索），
而不是在 token n-gram 哈希上继续做文章。仓库里已有 `run_knn_lm_baseline.py` 地基。

### D5 共训（Stage 3）—— 现在有了更强的动机

Stage 1b 显示最大衰减在**冻结**的 `value_proj`。
**只有训练能改动它。** 这条从"计划里的昂贵项"变成了"唯一能触及主因的手段"。

## 4. 建议的下一步（便宜、可否证、按顺序）

```text
[1] D3  weight_decay=0 消融         1 个 flag + 2 次训练   ← 最便宜，先做
       判据：PR(c_t) 是否显著上升？上升=正则化是部分原因

[2] D1a 局部窗口消融（反事实必要性）  GPU 天级              ← 最高价值
       判据：在"无记忆则必错"的任务上，PR(c_t) 是否上升？
             上升 => 塌缩由目标造成，可修
             不动 => 塌缩是架构/优化壁垒，D1 也救不了

[3] D2a 对比目标（对 cos(real,shuf) 施压）  GPU 天级
       判据：选择性是否恢复，且任务指标是否随之改善

[4] D1b 未见语料                      GPU 天级
       判据：在权重压不住的地方，记忆是否付钱

[5] 之后才回到 Stage 2.1（双层注入）/ Stage 3（共训）
```

**关键纪律**：`[1]` 和 `[2]` 都是**在改目标/正则，而不是改架构**。
这与我们过去三个月"改 reader 结构"的路线正交 —— 而 Stage 1b 已经证明
**架构旋钮（初始化、深度）不是主因**。
