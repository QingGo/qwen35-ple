## 3. 散文预测的"反转"是**长度混淆**，且符号随 regime 翻转

这是本轮最重要的发现，**必须在得出结论前报告**。

`classify_format.domain_fingerprint` 里的 `prose` 统计的是**出现了几种不同标记**（0–6），
不是每 token 频率：

```python
prose = sum(1 for m in _PROSE_MARKERS if m in low)   # _PROSE_MARKERS 有 6 个
```

**生成越长，越可能包含每一个标记**，标记计数随长度单调上升。
于是"哪个臂标记多"实际上主要由"哪个臂生成长"决定，而后者与语料无关。

配对长度校正：对每条目取配对差 $d_i = m_a - m_b$ 与长度差 $l_i = n_a - n_b$，
回归 $d_i = c + b\,l_i$；**截距 $c$ 是"等长条件下"的臂差**，$b$ 是每 token 的标记斜率。

| 预测 | regime | 原始差 | **长度校正后 $c$** | 斜率 | 判读 |
|---|---|---|---|---|---|
| `code>wiki` | 0.8B | +0.0333 | **+0.0399 ± 0.0103** (p=5.7e−5) | +0.0019 | 存活 |
| | 2B | +0.3350 | **+0.2404 ± 0.0371** (p=4.4e−11) | +0.0047 | 存活 |
| | 4B | +0.0300 | **+0.0239 ± 0.0133** (p=0.036) | +0.0006 | 存活 |
| `wiki>code` | 0.8B | +0.6933 | **+0.4159 ± 0.0458** (p=5.4e−20) | +0.0790 | 存活（缩水 40%） |
| | 2B | **−0.6800** | **+0.5832 ± 0.0809** (p=2.8e−13) | +0.0633 | **符号翻转 → 通过** |
| | 4B | **−0.8467** | +0.0098 ± 0.0668 (p=0.44) | +0.0823 | 归零 → **不可识别** |
| `stem>wiki` | 0.8B | +0.0017 | +0.0018 ± 0.0017 (p=0.15) | −0.0000 | null |
| | 2B | +0.0017 | +0.0041 ± 0.0026 (p=0.057) | −0.0001 | null |
| | 4B | +0.0000 | +0.0026 ± 0.0033 (p=0.22) | −0.0002 | null |

**三点结论：**

1. **`wiki>code` 的原始符号完全由长度决定，不是内容。** 2B 上 raw 是 **−0.68**，
   等长校正后变成 **+0.58（p=2.8e−13）** —— 预注册预测**通过了**；
   4B 上 raw 是 **−0.85**，校正后是 **0**（不可识别，因为 code/stem 有 95%+ 卡在 32 token）。
   同一个预测在两个骨干上 raw 都是"反转"，校正后一个是强正、一个是零。
2. **`code>wiki` 是唯一在三个骨干上、raw 与校正后都稳定通过的预测**，
   它是最干净的复现证据（0.8B +0.0399，2B +0.2404，4B +0.0239）。
3. **round 162 §3.7 的 0.8B 散文数字也被同一混淆放大了 40%**
   （+0.6933 → +0.4159）。它**仍然高度显著**，所以 0.8B 的结论没被推翻，
   但**幅度被高估**，而且当时从未做这个检查。

## 4. 综合结论

- **描述子层面的内容依赖在 2B 与 4B 上都复现，且比 0.8B 更强**（粗分类法主判决在两处都翻转）。
- **`code` 方向性预测在三个骨干上都复现**，且都通过长度校正。
- **`prose` 方向性预测在三个 regime 里都被长度混淆**；原始符号随"哪个臂生成更长"翻转，
  校正后三个都是正的（0.8B +0.416、2B +0.583、4B +0.010），
  2B 上还达到了预注册的显著性。
- 按**冻结的判定规则**，2B 与 4B 都是 **`PARTIAL`**（生成长度 ✓、描述子 ✓、两条强预测 ✗），
  不给它升格。但预注册第 5 节的三种结局里，这既不是干净的 `REPLICATES`，
  也**不是 `FAILS_TO_REPLICATE`**：唯一失败的那一项已定位为**测量伪影**。
- 新发现的限制：2B/4B 的"非饱和"只对**答案格式天花板**成立，
  `--qa-max-new-tokens 32` 在 code/stem 上成为新约束（94–99.8% 触顶）。

**对论文的含义**：

1. §3.7 的正面结果**跨骨干部分复现**，Limitations 第 2 条（"只有 600 条 / 一个骨干 /
   一个配方"）可以收紧：现在是三个骨干、同一预注册规则、同一分析脚本。
2. §3.7 的两条方向性预测中，`prose` 那一条的**幅度必须改用长度校正后的数字**，
   并且要写明原始数字被长度混淆；`code` 那一条可以原样保留。
3. Method Audit 应新增一条：**这是一个真实存在、当时没被检查的混淆**，
   它是在换骨干时才暴露出来的——因为换骨干改变了各臂的生成长度排序，
   从而把混淆的符号翻了过来。这正是"只有换条件才能发现的检查缺口"的一个实例。
