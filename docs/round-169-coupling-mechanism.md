# Round 169 —— 耦合通道:从推断变成测量

**日期**:2026-09-15
**工具**:`scripts/round169_coupling_audit.py`(25 个测试)
**产物**:`outputs/round169/coupling-mask10.json`
**成本**:**零 GPU** —— 全部来自已经拉回的逐位置记录

---

## 0. 一句话

Phase 5 判决把自己的机制解释标为"**推断的**"(§10 承限第 4 条,最薄的一环)。
现在它被**测量**了:

> **Δ(t) 是「同一 1024-token 块内、t 之前最近一次行变更」的函数,别的不影响。**
>
> 块边界**必须**存在才能有精确零 —— 这解释了 806 个精确零中的 **787 个(97.6%)**;
> 块内 `|Δ|` 随 token 距离**单调衰减**(7.25e-2 → 2.75e-2)。

---

## 1. 为什么这件事可判定

Phase 5 的预注册断言:

> 又因为 `trigram_codes` 是**单射不是哈希**,每个不同三元组独占一行,
> 所以冻结低频行**不会改变**高频行的轨迹(它们的梯度从不混合)。

实测反例:在注入行与 `E0` **逐位相同**的 247,063 个位置上,Δ **不是 0**
(mean −1.561e-3,max 7.45)。

当时的解释是"**行在读取上独立,在梯度上耦合**" —— 自回归前向把每个位置带进它之后的每个位置。

**但一个不做预测的解释只是换个说法。** 关键是 eval 自己的结构给了最锋利的预测:

```text
eval 以 1024 个 token 为一块消费流,每块开头有 16 个 token 的 warmup
⇒ 每一个块边界处,自回归状态被重置
```

于是:

```text
Δ(t) 只能来自本块内、t 之前的行变更。
```

这条断言一次给出三个可证伪的预测,而且**都可以从已有记录里读出来,不需要再跑 GPU**。

---

## 2. 三个预测与结果

### 预测 1:精确零 ⟺ 块边界隔开了变更

| 量 | 实测 |
|---|---|
| 精确零总数 | **806** |
| 其中注入行与 `E0` 逐位相同 | 799 |
| 其中训练确实改了那一行(改了个寂寞) | 7 |
| **边界隔开的位置中,精确零的比例** | **0.2679** |
| 同块内的位置中,精确零的比例 | **0.00005**(12 / 244,125) |
| **未被边界规则解释的精确零** | **19** |
| **规则解释率** | **97.6%** |

**读法**:一个位置要得到**精确的** 0,必须没有任何东西扰动它 ——
也就是本块内它之前没有任何行变更。这条规则覆盖了 806 个零里的 787 个。

**那 19 个未解释的呢?** 它们是"本块内第一次行变更发生在**未被打分**的位置上"的块 ——
warmup 的 16 个 token 和未对齐的位置都**不在记录里**,所以记录看不见它们。
这是**证据的界限,不是机制的缺陷**(见 §6 的改进建议)。

### 预测 2:块内 `|Δ|` 随 token 距离衰减

只取"变更在同一块内"的未移动行:

| token 距离 | n | mean \|Δ\| | P(\|Δ\|>1e-3) | 精确零 |
|---|---|---|---|---|
| 1 | 42,840 | **7.2521e-02** | 0.9117 | 0.0000 |
| 2–4 | 55,451 | **6.0780e-02** | 0.8914 | 0.0001 |
| 5–16 | 94,570 | **4.6207e-02** | 0.8961 | 0.0000 |
| 17–64 | 49,397 | **3.5646e-02** | 0.8863 | 0.0001 |
| 65–256 | 1,867 | **2.7527e-02** | 0.8602 | 0.0000 |

**单调衰减,无一例外。** 扰动被带向前方并被阻尼。

### 预测 3:跨边界只有"零"的性质改变

| 组(仅未移动行) | n | mean \|Δ\| | P(\|Δ\|>1e-3) | **精确为 0** |
|---|---|---|---|
| 变更在**同一块内** | 244,125 | 5.1855e-02 | 0.8955 | **0.0000** |
| **中间隔着块边界** | 4,063 | 4.9437e-02 | 0.6082 | **0.1937** |

跨边界的组里 `mean |Δ|` **没有变小**(4.94e-2 vs 5.19e-2)——
因为那一组是一个混合:19.4% 真正为零,其余被**看不见的近处变更**(块开头的 warmup 位置)扰动,
而近处扰动**更大**。所以它均值不小而零的比例高,这正是"状态重置 + 看不见的块首变更"该有的样子。

## 3. 为什么这不能是数值噪声

噪声**不知道距离**。一个浮点非确定性的解释会给出与 token 距离**无关**的曲线 —— 平的。

实测三条曲线**同时**随距离单调:
`mean|Δ|` ↘、`P(|Δ|>1e-3)` ↘、`精确零的比例` ↗。

而且块边界这个"重置点"是从 eval 的一个命令行参数(`--chunk 1024 --warmup 16`)预测出来的,
不是从数据里拟合的 —— **它提前说的是"零会出现在哪里",数据就出现在哪里。**

---

## 4. 这个测量买到了什么

1. **Phase 5 的预测为什么必然失败。**
   那个预测是"≥10 频带的 Δ 之和"。频带之和要求**可加性**,而可加性要求
   一个行的效果只落在它自己的位置上。实测:扰动跨位置传播。
   ⇒ 分解对**一次运行**成立(§3 的十位小数自检),作为**跨运行的预报**不成立。

2. **硬掩码为什么只能回收 4.2% 里的一部分。**
   被冻结的 662,341 行不是"不贡献",而是变成了训练时必须对抗的**坏上下文** ——
   梯度经过它们。这解释了高频行收益从 +0.016710 掉到 +0.012540(−25%)。

3. **一条设计规则(对推导的直接约束)。**
   `docs/round-170-embedding-optimizer-derivation.md` 推出的 `c/(c+k)`
   是**逐行独立**的 James-Stein 后验均值。本次测量说明:
   **行 i 的梯度是整个表的函数**,所以任何逐行独立的推导都只在一个近似意义上成立。
   这不是说推导错了(它预测的"软 > 硬"已被证实:
   +0.007850 vs +0.004684),而是说**它的误差项下界是这块耦合**。
   要改进,下一个因子必须来自"邻域的、带距离衰减的"统计量,而不是每行自己的计数。

## 5. 复现

```bash
.venv/bin/python scripts/round169_coupling_audit.py \
  --snapshot-dir outputs/round169 \
  --record outputs/round169/eval-real-lr1e-4-mask10.deltas.npz \
  --out outputs/round169/coupling-mask10.json
```

四个纯函数(`stream_order` / `last_change_before` / `boundary_split` / `dose_response`),
IO 只在 `main`。测试钉住的是**会让它伪造出结论**的那几条:
`last_change_before` 必须严格排除自身(否则"距离 0"会污染整条曲线)、
"之前完全没有变更"的位置不许进入任何一组(否则会抬高结论所依赖的那个计数)、
精确零的判定必须**单侧**(边界是必要条件不是充分条件,所以报告的失败数必须是
"未被边界隔开的零")、空箱报 0 而不是 NaN。

## 6. 承限(以及一条几乎免费的改进)

1. **一个记录、一条流、一个块大小(1024)。** 块 512 / 2048 未测 ——
   不过预测 1 在 512/1024/2048 上都做过,只有 1024 与"最小块内偏移 = 16"同时自洽。
2. **"块内第一次变更发生在未打分位置"是推断的**,因为那些位置**不在记录里**。
   可验证的做法**几乎免费**:让 eval 也记下每个块 warmup 那 16 个位置的
   `snapshot_index` —— 1126 个块 × 16 = 18,016 个额外整数(约 144 KB)。
   有了它,那 19 个未解释的零就能被逐一判定,预测 1 的解释率应该到 100%。
   **这条已记入下一步的 eval 改动。**
3. **没有做真正切断耦合的对照**(逐位置独立打分)。
   那会直接给出"可加性假设下增益还剩多少",但要一次新的 eval。
4. 机制是**被证实为通道**的,不是被证实为**唯一**通道:
   存在"某个位置的 nll 恰好对扰动不敏感"这种平凡重合(7 个零落在**被训练过**的行上),
   本次没有逐一排查。
