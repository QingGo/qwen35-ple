# Round 169 Phase 6/7 判决 —— nats 线存活,并且第一次在 argmax 上兑现

**日期**:2026-09-15
**闸门规则**:`scripts/round169_top1_verdict.py`,**先于任何 top-1 数据冻结**
**判定**:`GAIN`(t = +96.92,阈值 3.0)
**附带**:软收缩 `c/(c+k)` **击败**硬掩码 —— 推导的定性结论成立

---

## 0. 一句话

闸门判 **GAIN**:在骨干最不确定的尾部(46.3% 的位置),
top-1 命中率从 **2.52% 升到 8.15%(3.23×)**,配对 t = **+96.92**(阈值 3.0,余量 32 倍)。
**+1.925 nats 不是 log-loss 的假象 —— 它改变了模型会说什么。**

同一个 eval 顺手给出的第二个结果:**软收缩 +0.00784955 > 硬掩码 +0.00468403**。

---

## 1. 闸门先于数据冻结的规则

```text
GAIN  ⇔  tail 上 frozen − none 的配对 top-1 提升 > 0  且  t ≥ 3
FLAT  否则
tail  =  backbone 困惑度 ≥ 2 nats 的位置(按 nll_none 选取)
```

预注册的措辞(写在 `run_round169_phase6.sh` 的头部注释里):

> A FLAT verdict stops the whole NLL-optimisation line: if a 6.9x probability
> improvement on the tail does not move the argmax, then the currency this project
> has been optimising is not the currency of any capability.

**kill 条件没有触发。**

## 2. 结果

尾部 = 205,449 / 443,460 个打分位置(**46.3%**)。

| 臂 | top-1(全体) | top-1(尾部) |
|---|---|---|
| none(纯骨干) | 0.4727 | **0.0252** |
| frozen(冻结行注入) | 0.4892 | **0.0815** |
| trained(训练后注入) | 0.4891 | 0.0853 |

| 比较 | Δ top-1 | SE | t |
|---|---|---|---|
| **frozen − none** | **+0.05631** | 0.00058 | **+96.92** |
| trained − none | +0.06013 | 0.00060 | +100.47 |

**VERDICT: GAIN**

读法:在骨干自己都拿不准的位置上,冻结行注入把"猜对"的比例提高到 **3.23 倍**。

---

## 3. 这个判决为什么不可疑

1. **规则写在代码里、先于数据**;"只会放行"的方向被专门堵死
   (delta 为 0、为负、为正但 t<3、记录缺 hit 字段 —— 四种都返回 FLAT)。
2. **配对检验**,不是两个独立比例。t = 96.92 是阈值 3.0 的 **32 倍**,
   不是勉强过线。
3. **尾部按 `nll_none` 选取,两臂打分的是同一批位置**,不存在选择性偏差。
4. 同一次 eval 复现了 nats 侧的已知量(纯骨干 2.74499 nats),说明 eval 本身没变。

---

## 4. 它证明了什么、**没有**证明什么

### 证明了

> **PLE 行表改变的是模型"会说什么",不只是它的对数损失。**
> 这是本项目第一个在**非对数货币**上兑现的证据。

此前的每一项结论都活在 nats 里(+0.176 nats、65.6% 集中在前 1%、
按 surprisal 分带的增益…),而 nats 是日志量,天然被"模型非常错"的位置主导。
一个 6.9× 的概率比作用在 3.4e-4 的底概率上,可能什么决策都不改变 ——
**这正是这条线要被 kill 的理由。它没有成立。**

### 没有证明

1. **泛化。** 尾部上模型仍然错 **91.9%**,绝对命中率只有 8.15%。
   这是"把无望的位置变成偶尔猜对",不是"模型变好了"。
2. **整体 top-1 只动了 +1.65 点**(0.4727 → 0.4892,相对 +3.5%),
   因为尾部占 46.3% 而那里只有 8% 命中。
3. **增益的形状是记忆化的。** 按行证据分带,增益单调地长在高计数行上:
   `[10,49] +0.00164 → [50,199] +0.01596 → [200,+] +0.02147`,低计数带为负。
   也就是说,注入在"这个三元组我见过很多次"的位置上最有价值 ——
   **这是对记忆化续写的检索,不是对未见组合的推断。**

⇒ 当前最准确的一句话:
**PLE 的价值 = 记忆/检索价值,现在实测在 argmax 上兑现了;它不是学习价值。**

## 5. 附带结果:软收缩击败硬掩码

Phase 6 的 A/B(同阈值、同 lr、同 epoch、同 reader,**唯一差别是低频行被收缩还是被冻结**):

| 臂 | Δ (nats) | 相对注入收益 +0.17593 |
|---|---|---|
| baseline(全训,无掩码) | −0.0027166083 | — |
| hard(≥10 冻结) | +0.0046840290 | 2.66% |
| **soft(k=10,`c/(c+k)`)** | **+0.0078495538** | **4.46%** |
| soft / hard | **1.676 ×** | |

**推导的定性结论成立**:平滑收缩 > 硬截断。
机制上也自洽 —— §phase5 判决的表显示硬冻结会让高频行的收益掉 25%,
因为被冻结的行成了训练时必须对抗的坏上下文;软化把那个上下文变好。

### 一个值得记下但**不能声称**的巧合

Phase 5 为**硬**臂预注册的预测是 **+0.0074002256**,硬臂偏了 13.6 倍容差;
而**软**臂落在 **+0.0078495538** —— 距那个数 4.49e-4(2.25 倍容差)。

那个预测是"≥10 频带之和",它隐含地假设低频行**完全不贡献**。
软收缩做的正是"让低频行贡献一点点,而不是零也不为负"。
所以那个数字描述的**更像软区间而不是硬区间**。

**但这只是观察,不是结论**:软臂移动的是另一组行,那个预测从来不是关于它的。
要把它变成结论,必须另立一级、预注册一个新预测。

## 6. 对路线的影响

FLAT 是 kill 条件,没有触发 ⇒ **nats 线继续**。

但下一个该测的**不是 k 扫描**。k 扫描给出的是曲线形状,而定性结论已经成立;
它不触及本项目最弱的一环。真正的问题是:

> **尾部的增益,是不是只来自"背下来的三元组"?**

判据是现成的:同一个注入,在**训练流里只见过 1–2 次的三元组**上值多少?
如果只在见过几百次的三元组上有增益,那这条线的天花板就是"更省参数的 n-gram 表",
和"0.8B 通用性能"是两件事 —— 而这个区别决定了 Paper B 能不能写。

**所以下一步是把尺子换成任务形状的**(LongTail-Swap 式探针:从我们自己的
留出流生成"可接受/不可接受"句对),而不是在同一把尺子上再量一遍。

## 7. Phase 6 的失败与修复

Phase 6 的闸门 eval 跑完 rc=0、669 秒,产出的记录里**没有 `hit_*` 字段** ——
机器上那份 `scripts/round169_eval_rows.py` 是 100 分钟前的版本。
闸门工具拒绝读它(`ValueError: record is missing hit_none / hit_frozen`),
**这是唯一发出声音的防线**,也是这次代价是 11 分钟而不是一整条错误结论的原因。

Phase 7 修好了它,并在花 GPU **之前**加了两道守卫:
**guard A** eval 脚本必须含 top-1 能力(1 秒拒绝);**guard B** 缓存记录必须**带** hit 数组。
完整教训写在 `docs/gpu-utilisation-playbook.md` §2.13 与 §3.1。

## 8. 承限

1. **一个域(wiki)、一条留出流**;冻结骨干 + 冻结读出。
2. 尾部是**按 none 臂的困惑度事后选取**的,所以 8.15% 不是通用准确率,是条件准确率。
3. 闸门只回答"是否改变 argmax",不回答"改变得对不对得有道理" ——
   模型仍然错 91.9%,而且我们不知道那 8.15% 里有多少是"蒙对了重复的三元组"。
4. 软/硬 A/B 是**单点 k=10**;曲线的形状、最优 k 都未测。
5. 增益仍然只覆盖 667,404 行的子集,整表可训练性未证。
