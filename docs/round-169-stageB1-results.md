## 0. 一句话

**行确实能被推动(99.98% 的行动了,位移是原库量级的 2.3 倍),但推动的方向把损失弄坏了:
`ROWS_HARMED`。** 而这一级顺带测出了全项目**第一个净正向的注入读数**——
**冻结行比纯骨干好 0.176 nats**,这是我们此前从未测过的对照。

## 1. 主结果

三个 arm,同一批 **450,972** 个位置(留出流中三元组出现在训练流里的那些),
同一冻结骨干、同一冻结 reader、同一注入层:

| 臂 | 平均 NLL | 相对纯骨干 |
|---|---|---|
| `none` 纯骨干(无 reader、无注入) | **2.74499** | — |
| `frozen` 冻结行注入 | **2.56906** | **−0.17593** |
| `trained` 训练后行注入(lr=1e-3, 4 epochs) | **2.90033** | +0.15534 |

```
Delta = L_frozen − L_trained = -0.33127 nats      (SE 见 eval-real.json)
```

按预注册 §3:`Δ ≤ −0.05 且 |Δ| > 3·SE` ⇒ **`ROWS_HARMED`**。

### 1.1 零假设对照:有信息的移动与无信息的移动差 12 倍

| 臂 | 对着什么训练 | Δ (nats) |
|---|---|---|
| `real` | 真实下一 token | **−0.33127** |
| `shuf` | **打乱的**下一 token | **−3.97576** |

**两者都伤害冻结行,但无意义的移动伤害大 12 倍。**

这是预注册 §3 里 `Δ_shuf ≤ 0.01` 那条对照的**目的所在**,而且它这次给出的不是一个
"对照干净地塌到零",而是一个更强的结果:**对照臂本身就证明了这个系统对扰动极其敏感,
而真实目标至少指向了一个比随机好 12 倍的方向。**

⇒ `ROWS_HARMED` **不是**"我们动了什么东西"的伪影,而是**内容特异的**:
**任何**移动都有害,但只有有信息的移动才把伤害压到 1/12。

**这把 §2 的分频单调性接成了一个完整的机制故事**:

```text
罕见三元组(1-4 次出现 → 1-4 步梯度) ≈ 无信息移动 ⇒ 伤害 -0.52
高频三元组(数千步)                    ≈ 有信息移动 ⇒ 伤害 -0.18
real/shuf 之比 12× 正好是这两端的宏观版本
```

⇒ **冻结行处于该读出能用的一个局部最优点附近;移动的质量取决于该行拿到多少步梯度。**

### 1.2 这一级顺带测到的、此前没有的读数

**注入冻结行比不注入好 0.176 nats。** 这是全项目第一次在同一批位置、同一 reader 下
把"注入 vs 不注入"配起来测。此前 1.5c 的 `bb_final` 是**纯骨干**(它的 docstring 写明
"no reader, no injection"),所以我们一直缺这一格。

**它把"PLE 完全没用"这句话修正成:"冻结行的注入在这个 reader 下是净正向的,
只是净正向的幅度不足以支撑任何能力主张。"** 两者不矛盾,但前者是错的。

## 2. §4 的分频预测被证伪 —— 而且方向有信息量

预注册 §4 冻结的预测是:若 TD-11 的"梯度 ∝ 频率导致错配"成立,
增益应**峰在中频**。实测(Δ 为负 = 训练有害):

| 上下文频档 | n | Δ (nats) |
|---|---|---|
| `[1,1]` | 50,670 | **−0.52220** |
| `[2,2]` | 25,020 | −0.42189 |
| `[3,4]` | 27,441 | −0.36116 |
| `[5,9]` | 32,769 | −0.32348 |
| `[10,49]` | 58,102 | −0.25946 |
| `[50,199]` | 37,070 | −0.18797 |
| `[200,+]` | 62,071 | **−0.18039** |

**伤害随频率单调递减**——最罕见的上下文被破坏得最狠,**完全没有中频峰**。

⇒ **TD-11 的频率机制解释被证伪。** 取而代之的解释是**学习信号强度**:
罕见三元组在 990k token 的训练流里只有 1–4 次出现,每个只拿到 1–4 步梯度,
基本等于被注入噪声;高频上下文步数多、Adam 状态成熟,动得更有系统性。
这与 §2 记录的频率分布吻合:**87.5% 的三元组是单例**。

## 5. lr 容量曲线:1e-3 的发散**部分是 lr 伪影**

逐 epoch 训练损失(在同一训练流上):

| lr | ep0 | ep1 | ep2 | ep3 | 走向 |
|---|---|---|---|---|---|
| **1e-3** | 3.0555 | 3.1646 | **4.1414** | 3.4710 | **剧烈上升后回落,仍高于起点** |
| **1e-4** | 2.983(step100) → 2.996(step700) → **2.9797**(step1500) | … | | | **缓升后转降,已在起点之下** |

⇒ **`ROWS_HARMED`(lr=1e-3)里有一部分是学习率过大造成的,不是行不可训练。**
在 lr=1e-4 下,梯度下降**确实在降低**这个冻结读出的损失。

所以正确的读法不是"行不能被重塑",而是:

> **行可以被重塑,但只能极其温和地重塑;冻结行已接近该读出的可用最优点,
> 而 lr=1e-3 那样的大步会被"伤害 ∝ 步长"的机制吃掉。**

**`lr=1e-4` 臂的 eval 是把这个读法钉死的最后一格**:若 Δ(1e-4) 显著小于 |−0.331|、
甚至转正,则上面这句话成立;若 Δ(1e-4) 仍 ≈ −0.33,则说明连收敛的训练也救不回来,
`ROWS_HARMED` 才是一个关于行的绝对结论(在冻结读出下)。

## 7. 承限

1. **只训了 1.5% 的表**(667,404 / 3.2e8 行),不构成"整表可训练"的证明。
2. **基线是冻结骨干**,不是从零共训的骨干 ⇒ 即使行可推动,也**不能**推出"共训一定更好"。
3. **读出是冻结的**:本级的 `ROWS_HARMED` 是**关于这个读出**的结论,不是关于行的绝对结论。
   这正是 §2.1 那个零输出 reader 陷阱的另一面——读出是这条链上的约束方。
4. **lr 只测了两档**,是容量曲线的粗版;两档都不动才算"不可训练"。
5. `shuf` 臂重启过一次(同 seed,可复现),但它的 wall 时间不代表一次干净运行。
